# AI 분류 진행률 표시 (CHMO-991)

## 문제와 목표

기존 이벤트 상세는 서버 진행률과 무관하게 1초에 1%씩 최대 90%까지 증가했다. 작업마다 90%에 도달해 오래 멈추는 것처럼 보였고, 서버가 실제로 확인한 비율을 화면이 앞질렀다. 표시값을 최신 서버 진행률까지만 올리되, 분류 중임은 계속 알린다.

## 처리 흐름

`EventDetailPage`는 분석 중 2초마다 `GET /events/{eventId}`를 조회한다. 응답의 `progress.percent`가 `ChaseProgress`의 목표값이다. `advanceAnalysisProgress`는 75ms마다 남은 차이의 약 1/3씩 표시값을 높이고, 목표값에 도달하면 그대로 둔다. 응답이 없거나 더 낮으면 표시값을 임의로 올리거나 되돌리지 않는다. 진행 화면의 회전 표시는 이때도 계속 움직인다.

완료 응답이 오면 진행 화면을 즉시 접고 앨범 목록을 다시 읽어 결과 그리드를 보여 준다. 백엔드의 완료 100% 조회 유예 15초는 화면 대기 시간이 아니다.

## 판단과 검증

고정 90% 추정치는 수신 누락을 가려 주지만 매 작업이 같은 지점에서 멈춰 실제 처리 상태처럼 오해됐다. 최신 서버 값을 상한으로 쓰면 새 메시지가 없을 때 숫자가 멈출 수 있으므로 회전 표시를 유지한다. SQS 표준 큐와 2초 API 폴링은 모든 중간 퍼센트의 표시를 보장하지 않는다.

`analysisProgress.test.ts`가 0% 유지, 서버 상한, 역행 방지를 검증한다. 웹 전체 검증은 `npm run verify`로 수행한다.
