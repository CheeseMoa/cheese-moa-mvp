치즈모아 · ADA 수상작 차용 시안 v4

v3는 "토스처럼 안 보이기"를 목표로 삼다가 검증된 UX까지 같이 버렸다 — 하단 고정 CTA 제거, 영어 모노 라벨, 불균일 그리드, 작은 탭 타깃. ADA 수상작들은 정확히 반대로 한다: 네비게이션은 철저히 관습적이고, 개성은 콘텐츠 안에서 낸다. v4의 네 안은 각각 실제 ADA 수상작 한 개의 구조를 빌려 우리 콘텐츠를 얹은 것이다. 네 안 모두 §01의 UX 기본기를 예외 없이 지킨다.

01네 안이 공통으로 지키는 것

v3에서 깨뜨렸던 것들. 여기서부터는 협상 대상이 아니다.

하단 고정 CTA주요 행동은 항상 화면 아래 고정 · 전폭 · 높이 50. v3 D1·D6은 텍스트 링크와 FAB으로 숨겼다.
한글 라벨ALBUMS·52 FRAMES·NOT SHARED 같은 영어 모노 라벨 전면 폐기. v3 D2·D3의 지문이었고, 유치원 선생님에게는 그냥 못 읽는 글자다.
탭 타깃 44px모든 행·버튼·아이콘의 실제 터치 영역이 최소 44px. 목록 행은 62px 이상.
이름은 13px 이상앨범 이름 = 사람 이름이다. v3 D2는 8.5px 모노로 깔았다.
사진 위 글씨 금지이름·장수는 사진 밖에 둔다. v3 D3·D6은 사진 위에 겹쳐 배경에 따라 안 읽혔다.
균일 그리드같은 종류는 같은 크기. v3 D6은 크기를 정보로 썼는데, 훑을 수가 없어진다.
돌아갈 곳헤더 좌측 ‹ 뒤로는 모든 하위 화면에 존재. 어디서도 막히지 않는다.

B · 상태← Flighty (2023 Interaction 수상)추천

Flighty의 핵심은 카드가 곧 대시보드라는 것 — 비행 카드 하나에 경로·진행·지연이 전부 그려져 있어 탭하지 않아도 상황을 안다. 우리 서비스도 실은 상태 머신이다(업로드 → 분류 → 검토 → 공개). 그런데 지금은 그 흐름이 배지 한 개로만 있고, 선생님은 "내가 지금 뭘 해야 하는지"를 화면 어디서도 못 읽는다 — 이게 이용을 어렵게 만드는 진짜 원인이라고 본다. 모임 카드에 할 일을, 08 상단에 4단계 진행 축을 그렸다.

03정리

  1. 추천은 B(상태). "UX적으로 힘들어할 것 같다"의 원인이 지금 뭘 해야 하는지 화면이 말 안 해준다는 데 있다고 보고, 그걸 정면으로 푸는 안이라서. 개성도 "귀여움"이 아니라 "유능함" 쪽이라 유아틱과 가장 멀다.
  2. 네 안은 배타적이지 않다. 실제로 좋은 조합은 B의 상태 표시 + C의 홈 문장 + A의 모임 색·심볼이다. 셋 다 서로 다른 층(카드 내용 / 홈 최상단 / 식별 색)에 얹히기 때문에 부딪히지 않는다.
  3. BE 작업이 필요한 게 셋 있다. A·D의 모임 색 필드 · B의 모임별 할 일 집계 · C의 "다음에 할 앨범" 판정. C의 판정은 이미 FE에 있다(lib/reviewFlow.ts) — C가 BE 없이 오늘 당장 가능한 유일한 안이다.
  4. 이번엔 톤·색·서체를 일부러 안 건드렸다. 네 안 모두 Pretendard에 무채색 기반이다 — 먼저 구조를 고르고 그 위에 색과 서체를 입히는 순서가 맞다고 봐서. v3에서 그 둘을 한꺼번에 흔든 게 실패 원인 중 하나였다.
