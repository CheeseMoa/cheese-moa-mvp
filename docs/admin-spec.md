## 1. 목적

운영 중 나오는 질문에 DB 직접 조회 없이 답하기 위한 백오피스.

- "가입자·모임이 얼마나 늘고 있나"
- "어느 유치원이 실제로 쓰고 있나"
- "이 모임 상태가 지금 어떤가" (문의 대응)

**범위 밖**: 기관 관리자용 모임 내 관리, 결제/요금제, 고객 문의 시스템.

## 2. 확정 결정 3가지

### 2-1. 배포 위치 — 같은 리포 `/admin` 라우트

**판단 근거**

- 모바일 프레임(`PhoneShell`)은 라우터가 아니라 **페이지마다 개별로 두른다**(`src/router.tsx`, 21개 페이지가 각자 import). `/admin` 페이지는 안 두르면 그만이라 "모바일 셸과 섞인다"는 문제가 실제로는 없다.
- 재사용되는 것: `src/api/client.ts`(응답 봉투 언랩 + **401 리프레시 토큰 회전·in-flight 공유**), `src/api/errors.ts`, `src/lib/auth.ts`, `useApi`/`useMutation`, 타입 계약. 특히 리프레시 로직은 미묘해 다시 짜면 버그가 나기 쉽다.
- 배포·CI가 1개로 유지된다(Vercel 프로젝트 1개, `vercel.json`이 `/api/v1/*`를 실 BE로 rewrite).

**대가와 대응**

| 대가 | 대응 |
|---|---|
| 번들 증가 | 라우트를 `lazy()`로 분리(`/dev/components` 선례) — `/admin` 진입자만 받는다 |
| 학부모 뷰어와 같은 도메인 | 1차는 조회 전용이라 수용. 쓰기 액션이 들어올 때 재검토 |

### 2-2. 나중에 별도 리포로 격리하기 위한 규칙 3개 (지금부터 지킨다)

이 규칙을 지키면 격리는 "폴더 옮기고 Vercel 프로젝트 하나 파기"로 끝난다. 안 지키면 실 뽑듯 뜯어내야 한다.

1. **관리자 코드는 `src/admin/` 한 폴더에만.** 서비스 코드가 관리자 코드를 import하지 않는다(의존 방향 한쪽).
2. **공유는 바닥 인프라뿐** — `api/client.ts`·`lib/auth.ts` 등. 화면 컴포넌트는 서로 쓰지 않는다.
3. **BE 경로를 처음부터 `/admin/*`으로 분리.** 프론트를 떼어내도 BE는 그대로 둔다.

### 2-3. 인증 — 유저에 관리자 역할(role) 부여

**핵심 원칙**

> **기존 서비스 API는 role을 쳐다보지 않는다.** 관리자여도 자기가 멤버가 아닌 모임은 일반 화면에서 볼 수 없다. 전체 데이터는 `/admin/*` 전용 API에서만 보인다.

- role은 **더하는 것이지 바꾸는 것이 아니다** — 관리자 계정도 평범한 유저로서 모임 생성·업로드·검수·공개를 그대로 한다(테스트 계정으로 겸용 가능).
- 초기 관리자 지정은 DB 직접 변경으로 충분하다. ⚠ **계정 생성은 반드시 signup API로** — BE가 PIN을 BCrypt 해시로 저장·비교하므로 DB에 평문 행을 직접 넣으면 로그인이 영원히 실패한다(2026-08-04 실측). role 칼럼만 DB에서 바꾼다.
- 기본값은 일반 유저 — 기존 행은 마이그레이션 영향이 없다.
- 관리자 계정은 기존 `User`를 쓰되 비밀번호 해시를 PIN과 분리한다. `auth_method=ADMIN_PASSWORD` 토큰과 Cloudflare Access assertion을 백엔드가 검사한다. 일반 서비스 API 계약은 유지한다.
- **진입 플로우(CHMO-934)** — 기존 앱 호스트의 `/admin`에서 Cloudflare Access를 통과한 뒤, 비로그인·세션 만료 상태에는 **어드민 셸 안 데스크탑 로그인 카드**가 보인다. 카드는 닉네임과 15자 이상 비밀번호를 `POST /auth/admin/login`으로 제출하고, 성공하면 `GET /admin/me`를 재판정한다. 소셜 로그인은 관리자 인증 수단이 아니다. 비관리자 차단 화면의 [다른 계정으로 로그인]은 토큰을 지우고 카드로 되돌린다. 로그아웃은 서버 refreshToken 무효화 후 로컬 삭제를 수행한다. Access는 같은 앱 호스트의 `/admin*`, `/api/v1/admin*`, `/api/v1/auth/admin/login`을 하나의 애플리케이션으로 보호한다.

- **과금 줄**(CHMO-932 — BE A-3): 과금 범위(개인/기관) · 과금 소유자(닉네임 `#id` → 사용자 상세). **개인 범위**면 패스 상태(`이용 중 · ~까지` / `없음` — 패스가 없으면 올리는 사람의 장수가 줄어요) + \[패스 지급\], **기관 범위**면 과금 소유 기관의 접근 상태 배지(이용 중/유예/차단)·종료일·유예 종료(패스가 아니라 기관 기간이 업로드를 결정한다 — ADR 039). \[과금 범위 변경\]은 둘 다(구계약 응답이라 범위를 모르면 잠근다 — 모르는 값을 '개인'으로 단정하면 기관 모임에도 지급 버튼이 선다).
- **멤버 목록**: 닉네임 + **역할 칩**(비즈니스 `관리자`/`멤버` · **일반은 전원 `멤버`** — 일반 모임은 역할이 없다(ADR 020). 종전 '선생님/학부모'는 유치원 어휘인 데다 유형을 안 봐서 **일반 모임 멤버가 전부 선생님으로 보였다** — CHMO-932, `memberRoleLabel(role, groupType)`) + **기관 계정 칩**(계정 유형은 역할과 다른 축 — BE A-7 `members[].accountType`) + 승인 대기 칩, 합류일
- **이벤트 목록**: 이름, 날짜, 상태(빈/분석중/검수중/공개), 사진 수, 앨범 수, **마지막 업로드**(CHMO-932), 공개일
- **패스 지급 이력**(개인 범위만 — CHMO-932 BE A-8): 기간(1·3·7·30일) · 적용 구간 · 메모(+등록 시각·관리자 `#id`, 나면 `(나)`) · \[회수\]/`회수됨`(취소선). **운영자가 준 패스만** 보인다 — 스토어 구매는 별도 원장이고 만료 시각에만 함께 반영된다(ADR 045).

**패스 지급 다이얼로그**(`PassGrantDialog`) — 플랜 세그먼트(1·3·7·30일) + 메모(필수 500자 — 지급 이력에 그대로) → `POST /admin/groups/{id}/pass-grants`(201). "반영 뒤 ~까지"를 미리 보여 주는 건 **누적 규칙** 때문이다: 살아 있는 패스가 있으면 지금부터가 아니라 그 만료 뒤에 이어 붙는다(스토어 구매와 같은 규칙 — `lib/billing.passAccessUntilAfterGrant`). 기관 범위 모임은 서버가 VALID400으로 거절하고(버튼 자체가 안 선다) 메시지를 그대로 보여 준다. **회수**는 확인 다이얼로그 뒤 `DELETE /admin/pass-grants/{id}` — 지급분만큼 만료를 당기되 지금 이전으로는 줄이지 않고(스토어 환불 규칙) 이력은 남는다. 없는 지급(BILLING404)은 "다른 관리자가 처리했을 수 있어요" + 재조회.

**과금 범위 변경 다이얼로그**(`BillingScopeDialog` — CHMO-932, BE CHMO-912 `PUT …/billing-scope`를 처음 소비) — 범위 세그먼트(개인/기관) + 소유자 userId(사용자 화면의 `#번호` — 닉네임은 소셜 가입이라 여럿이 같을 수 있어 식별자가 못 된다) + 메모(필수 — 감사 이력). **기관 범위의 소유자는 기관 계정이어야 한다**는 규칙은 서버만 알아(VALID400) 소유자 칸 아래에서 받고, USER404도 같은 칸. 지금 값과 같으면 저장을 잠근다. 모임 소유권 이전(생성자 변경)은 이 값을 바꾸지 않는다(ADR 039 스냅샷).

**학부모 공유 비밀번호는 1차에서 노출하지 않는다** — 조회 전용 화면에 평문 비밀번호가 떠 있으면 화면 캡처 하나가 사고가 된다. 운영 문의는 선생님 본인 화면(05 학부모 공유 시트)으로 안내한다.

### 3-4. 기관 문의 (CHMO-811 — 어드민의 첫 쓰기 화면)

`/admin/inquiries`. 앱이 \[개인 | 유치원·기관\]으로 갈리면서(CHMO-803) 기관 계정은 도입 문의를 낸 뒤 **팀이 개통할 때까지 승인 대기 화면에 머문다**(CHMO-809). 그 개통을 지금까지 BE 개발자의 SQL이 하고 있었고, 이 화면이 그 자리를 대신한다. §6의 "B2B 기관 등록 검수"가 앞당겨진 것이다.

**필터 탭** — 진행 중(기본) / 개통 / 종료 / 전체. 각각 `status` 쿼리 값(`RECEIVED,CONTACTED` / `ONBOARDED` / `CLOSED` / `ALL`)이고, 생략 시 BE 기본값이 곧 '진행 중'이다.

| 컬럼 | 비고 |
|---|---|
| 접수일 | 정렬은 `createdAt,desc` 고정(`sort` 파라미터 없음) |
| 기관 | 기관명 + 유형(유치원·어린이집·학원·기타) · 지역 |
| 담당자 | 이름 + 역할(원장님·선생님·행정) — 역할은 선택 항목이라 `—` 가능 |
| 연락처 | `tel:` 링크. **마스킹하지 않는다** — 팀이 전화하려고 받은 값이고 이 화면은 관리자 전용(CHMO-802 정책) |
| 사용자 | 닉네임 · `#userId` · 소셜 수단(없으면 `PIN`) |
| 상태 | 접수됨 / 연락 완료 / 개통 / 종료 |
| 갱신일 | 마지막 전이 시각(`updatedAt`) |
| 상태 변경 | 주 동작 버튼 + `⋯` (아래) |

**전이 — 규칙이 없다.** 어느 상태에서 어느 상태로든 갈 수 있고 같은 값 재요청도 에러가 아니다(BE CHMO-810 결정: 관리자가 잘못 누른 값을 화면에서 직접 고칠 수 있어야 한다). 그래서 **개통·종료 행에도 액션이 뜬다** — 숨기면 실수로 누른 `CLOSED`를 되돌릴 방법이 UI에 없다. 초안의 `INQUIRY400`(이미 전이됨)은 폐기돼 존재하지 않는다.

**다만 셋을 나란히 두지는 않는다.** 같은 무게의 버튼 셋은 "지금 뭘 해야 하는지"를 지우고, 상태 이름이 적힌 버튼(`접수됨`)은 현재 상태를 말하는지 누르면 그리로 간다는 건지 읽히지 않는다. 그래서 **라벨은 동사**이고, 주 동작 하나만 버튼으로 세우고 나머지는 `⋯`로 접는다.

| 현재 상태 | 주 버튼 | `⋯` |
|---|---|---|
| 접수됨 | \[개통하기\] | 연락 완료로 표시 · 종료하기 |
| 연락 완료 | \[개통하기\] | 접수됨으로 되돌리기 · 종료하기 |
| 개통 | 없음 | **개통을 취소하고** → 접수됨으로 · 연락 완료로 · 종료로 |
| 종료 | 없음 | 접수됨으로 되돌리기 · 연락 완료로 표시 · 개통하기 |

`개통` 행에 주 버튼이 없는 이유는 셋 다 결과가 같아서다 — 어느 상태로 보내든 그 계정은 승인 대기 화면으로 돌아간다. 목적지는 셋 다 열어 두되(되돌릴 곳을 서버가 기억하지 않는다) `개통을 취소하고`라는 한 제목 아래 묶어, 무슨 일이 일어나는지를 항목마다 되풀이하지 않는다.

**상태의 뜻은 화면이 한 줄로 말한다** — 목록 위 "접수됨 · 연락 완료는 아직 진행 중이에요. **개통**하면 그 계정이 앱에서 모임을 만들고 사진을 올릴 수 있어요." 상태 이름만으로는 무엇이 달라지는지 알 수 없다.

| 확인 모달 | 언제 | 요지 |
|---|---|---|
| 개통 | `→ ONBOARDED` | "개통하면 이 사용자가 앱에서 모임을 만들고 사진을 올릴 수 있어요" + 사용자 쪽 다음 동작. **첫 이용 기간 폼을 품는다**(CHMO-931 — 아래) |
| 개통 취소 | **`ONBOARDED`에서 나가는 전이 전부** | "승인 대기 화면으로 돌아가요. **모임과 사진은 그대로 남고**, 다시 개통하면 이어서 쓸 수 있어요" |
| 종료 | `→ CLOSED` | "다시 진행하려면 사용자가 문의를 새로 내야 해요" |

개통 취소를 목적지(`CLOSED`)가 아니라 **출발지**(`ONBOARDED`)로 판정하는 이유: 사용자 화면에서는 `CLOSED`로 보내든 `RECEIVED`로 되돌리든 똑같이 승인 대기로 돌아간다. 목적지로 가르면 가장 파괴적으로 보이는 되돌리기만 확인 없이 나간다. 나머지(연락 완료 표시, 종료분 되돌리기)는 사용자 화면을 바꾸지 않는 운영 메모라 바로 나간다.

**개통은 첫 이용 기간 등록과 한 흐름이다(CHMO-931 — BE CHMO-912).** ⚠ 종전 "기관은 체험 기간이 없어 기간 없이 개통하면 첫날부터 막힌다"는 **BE CHMO-940(2026-10-16 운영 반영)으로 사실이 아니게 됐다** — 기관 계정은 가입할 때 서버가 체험 14일을 자동으로 넣는다(기존 기관 계정도 백필). 그래서 기간 없이 개통해도 체험이 남아 있는 동안은 올릴 수 있고, 체험이 끝나면 7일 유예 뒤 차단된다(BE `InstitutionAccessResolver`). 체험 기간은 사용자 상세 이력에 '가입 체험'으로 보인다(CHMO-932). 그래서 개통 확인 창(`InquiryOnboardDialog`)이 §3-9의 기간 폼(이용 시작·종료일 · 입금액 · 입금일 · 입금자명(기관명 미리 채움) · 세금계산서 번호 · 메모)을 품고 `PATCH …/{id}` 본문에 `subscriptionPeriod`로 동봉한다 — BE가 상태 전이와 기간 등록을 한 트랜잭션으로 처리한다(기간 등록이 거절되면 상태도 안 바뀐다). "첫 이용 기간을 함께 등록해요" 체크를 풀면 기간 없이 개통하는 길도 남긴다(과금 적용 전이거나 입금이 아직일 때) — 다만 그 결과("과금 중이면 첫날부터 막힌다 · 입금 확인되면 기관 구독에서 등록")를 안내 상자로 말한다. 확정 버튼 라벨이 `기간 등록하고 개통` / `기간 없이 개통`으로 갈려 어느 쪽인지 누르기 전에 읽힌다. 성공 토스트는 등록한 종료일까지 말한다.

**전이 후** — 성공 토스트 + **그 행만 제자리 갱신**(PATCH 응답이 목록 행과 같은 형태라 재조회가 없다). 필터와 어긋나게 된 행도 그 자리에 남긴다: 방금 누른 행이 사라지면 잘못 누른 값을 되돌릴 대상이 화면에서 없어진다. 다음 조회(탭·페이지 이동·\[새로고침\])에서 빠진다.

**실패 2종** — `INQUIRY404`(없는 문의)·`INQUIRY409`(되돌리기 충돌 — 그 사용자에게 진행 중 문의가 이미 있다, CHMO-802의 "진행 중 1건" 제약)는 둘 다 "화면이 든 목록이 낡았다"는 뜻이라 안내 후 목록을 다시 읽는다.

**대시보드 카드** — "대기 중 기관 문의 N건"(→ 이 화면). 전용 카운트 API가 없어 목록을 `size=1`로 부르고 봉투 `pageInfo.totalElements`만 읽는다.

**전이 이력은 화면에 없다** — 누가·언제·from/to는 테이블이 아니라 CloudWatch 액세스 로그가 정본이고(BE [ADR 017](https://github.com/CheeseMoa/CheeseMoa-BE/blob/develop/docs/decisions/017-access-log-as-audit-record.md)) 조회 API가 없다. 화면에는 마지막 전이 시각만 둔다.

### 3-5. 신고·문의 (CHMO-862 — BE CHMO-861)

`/admin/reports`(사이드바 `신고·문의` — 대시보드 바로 아래). 앱의 신고·문의 폼(BE CHMO-860)으로 들어온 건을 보고 **답한다**. 회원에게 이메일이 없어(소셜·PIN 가입) **팀의 답은 이 화면의 답변이 유일한 경로**다 — 답변은 사용자 앱의 \[신고·문의\]에 서고, 첫 답변은 푸시(`REPORT_ANSWERED`)로 알린다.

**화면 구성 — 목록 + 오른쪽 곁 패널.** 행을 누르면 목록 오른쪽에 상세 패널(440)이 붙는다. 모달이 아닌 이유: 신고·문의는 한 건씩 읽고 답하고 다음 건으로 넘어가는 일이라, 목록을 가리면 다음 건을 누를 수 없다. 연 건은 URL `?id=`에 둬 새로고침·주소 공유에도 같은 건이 열린다(히스토리는 replace — 훑을 때마다 뒤로가기가 쌓이지 않게). 패널이 열리면 표가 좁아져 사용자·답변 칸을 접고 시각에서 연도를 뗀다(전부 패널에 있다).

**필터** — 상태 탭 처리 대기(기본) / 답변 완료 / 종료 / 전체(`status` 값 `RECEIVED,IN_PROGRESS` / `ANSWERED` / `CLOSED` / `ALL` — 생략 시 BE 기본값이 처리 대기) + 유형 칩 전체 / **신고만**(`DELETION_REQUEST,INAPPROPRIATE`) / 앱 오류 / 사진 분류 / 계정·참여 / 제안·기타. 탭이 "무엇을 할 차례인가", 칩이 "그중 어떤 것"이라 칩이 한 단계 약하다.

| 컬럼 | 비고 |
|---|---|
| 접수 | 정렬은 `createdAt,desc`(동률 id DESC) 고정 — `sort` 파라미터 없음 |
| 유형 | **신고 2종(삭제 요청·부적절 신고)만 붉은 배지**(서비스 `warn`) — 사진이 걸린 일이라 먼저 눈에 걸려야 한다. 문의 4종은 중립 회색 |
| 내용 | 내용 앞 60자(2줄) + 무엇에 관한 건인지(`[사진] 모임명` · 모임명 · `첨부 있음`). 목록 행엔 **이벤트명이 없어**(상세에만) 사진 신고는 모임까지만 말한다. 지워진 모임은 `모임 #N (지워진 모임)` |
| 사용자 | 닉네임 · `#userId` · 소셜 수단(없으면 `PIN`) |
| 상태 | 접수됨(주황) / 확인 중(갈색) / 답변 완료(초록) / 종료(회색) — 새 색 없이 이벤트 배지 토큰 재사용 |
| 답변 | 마지막 답변 시각(재답변도 갱신) |

**상세 패널** — 위에서부터 ① 상태 배지 + 접수 시각 + 상태 변경 ② (사진 신고) 신고한 사진 — 원본 presigned를 패널 폭에 맞춰 그리고 누르면 크게 본다, `모임 #N · 모임명 › 이벤트명 · 사진 #N` + \[모임 상세에서 보기\], 지워진 사진은 점선 자리에 "삭제된 사진이에요". **어드민엔 사진 숨김·삭제 기능이 없어** 신고 사진 아래에 "모임 관리자에게 연락해 앱에서 지우도록 요청해 주세요" 한 줄을 둔다(운영 1차 절차 — 조치 기능은 필요해지면 별도 티켓) ③ 내용 전문 + 첨부 스크린샷(최대 3 · 누르면 확대) ④ 보낸 사람 — 사용자 · 모임(사진 신고는 ②가 이미 말해 생략) · 모임 역할(모임을 나갔으면 "지금은 멤버가 아니에요") · 기기(`앱 2.4.0+28 · iOS 26.5 · iPhone18,1`, 없으면 `—`) · 이어서 문의(누르면 그 건으로 패널이 넘어간다) ⑤ 답변.

**답변** — textarea(2,000자 카운터 · BE와 같은 trim 후 1~2,000자) + \[답변 보내기\] → 토스트 "답변을 보냈어요 · 사용자에게 알림이 갔어요" + 행 제자리 갱신(응답이 상세 형태라 재조회 없음). 이미 답한 건은 **원문이 채워진 채** \[답변 고치기\]이고 "고친 답변은 알림을 다시 보내지 않아요"를 한 줄로 알린다(BE — 오타 수정이 알림 폭탄이 되지 않게). 내용이 그대로면 버튼이 잠긴다. 첫 답변 안내 문구는 "알림을 끈 사용자는 앱에서만 볼 수 있어요"까지 말한다(`pushEnabled=false`면 BE가 발송을 생략한다).

**상태 변경 — 규칙이 없다**(기관 문의 CHMO-810과 같은 BE 결정). 라벨은 동사이고 셋을 나란히 두지 않는다(§3-4와 같은 이유):

| 현재 상태 | 주 버튼 | `⋯` |
|---|---|---|
| 접수됨 | \[확인 중으로 표시\] | 종료하기 (+ 답변 있으면 답변 완료로 표시) |
| 확인 중 | 없음 — 다음 할 일은 상태가 아니라 **답변 작성** | 접수됨으로 되돌리기 · 종료하기 (+ 답변 완료로 표시) |
| 답변 완료 | 없음 | 접수됨으로 되돌리기 · 확인 중으로 되돌리기 · 종료하기 |
| 종료 | 없음 | 접수됨으로 되돌리기 · 확인 중으로 되돌리기 · 답변 완료로 표시(답변 있을 때) |

`답변 완료로 표시`는 **답변이 있을 때만** 메뉴에 둔다 — 답이 없으면 BE가 VALID400으로 거절하고, 답변 완료는 \[답변 보내기\]가 만드는 상태다. 확인 모달은 하나뿐: **답변 없이 종료**(사용자가 답을 받지 못한 채 끝난다). 나머지 전이는 팀 내 표시라 바로 나간다. 전이 후엔 기관 문의와 같이 그 행만 제자리 갱신하고 필터와 어긋나도 남긴다(다음 조회에서 빠진다).

**실패** — `REPORT404`(없는 건 — 사용자가 계정을 지우면 신고·문의도 함께 사라진다)는 목록이 낡았다는 뜻이라 안내 토스트 → 패널 닫기 → 목록·배지 재조회(딥링크 `?id=` 조회도 같은 길) · `VALID400`은 인라인(답변 칸 아래 "1~2,000자" / 상태 줄 아래 "답변을 먼저 보내야 답변 완료로") · 401은 서비스 로그인으로 보내지 않고 메시지만(어드민 로그인 카드가 재로그인 표면) · `ADMIN403`은 셸 가드.

**처리 대기 건수** — 사이드바 `신고·문의` 라벨 곁 옐로우 수(1건 이상일 때만)와 대시보드 `처리 대기 신고·문의 N건` 카드. 전용 카운트 API가 없어 목록을 `size=1`로 부르고 `pageInfo.totalElements`를 읽는다. **셸(AdminLayout)이 한 번만 조회해** 둘에 나눠 준다(각자 부르면 대시보드 진입마다 같은 요청이 두 번) — 화면 이동·\[새로고침\]·답변·전이 성공 때 다시 읽는다(새 신고는 앱에서 들어오고 어드민엔 푸시가 없다). 토스트는 패널이 열려 있으면 하단 가운데로 옮긴다(우측 하단이 패널의 \[답변 보내기\] 자리).

**답변·전이 이력은 화면에 없다** — 누가·언제는 CloudWatch 액세스 로그가 정본이고(BE ADR 017) 답변 본문은 PayloadSanitizer가 마스킹한다. 화면엔 마지막 답변 시각과 답한 관리자 `#userId`만 둔다.

### 3-6. 이벤트 팝업 (CHMO-928 — BE CHMO-926)

`/admin/popups`(목록) · `/admin/popups/new`(작성 — 복제는 `?from=:id`) · `/admin/popups/:popupId`(수정). 사이드바는 처리·조회 메뉴와 묶음을 갈라 **`알림·홍보`** 아래에 둔다(사용자에게 먼저 말을 거는 도구라 성격이 다르다). 앱(CHMO-927)은 틀만 갖고 내용은 서버가 내려줘서, **팝업을 바꿀 때 앱을 업데이트하지 않는다** — 이 화면이 그 내용을 만든다.

**목록** — 상태 탭 전체(기본) / 노출 중 / 예정 / 종료 / 꺼짐(`status` 값 `LIVE`·`SCHEDULED`·`ENDED`·`OFF` — 저장값이 아니라 **조회 시각 파생**이라 시간이 지나면 탭을 옮겨 다닌다, OFF가 기간보다 우선). 컬럼: 이미지 썸네일(4:5) · 팝업(관리용 이름 + `[버튼 문구] · 링크 호스트`) · 상태 배지(노출 중 초록 · 예정 갈색 · 종료 옅은 회색 · 꺼짐 진한 회색 — 새 색 없음) · 기간(KST) · 대상 · 언어 · 우선순위 · **켜기 스위치** · `⋯`(수정 · 복제해서 새로 만들기 · 삭제). 행을 누르면 수정 화면이고, 스위치·`⋯` 칸은 셀 여백까지 행 클릭을 막는다(빗겨 누른 손이 수정 화면으로 튀지 않게). 목록 위 한 줄이 노출 규칙을 말한다: 앱은 홈에서 **한 번에 하나만** 띄우고 노출 중이 여럿이면 우선순위 큰 것부터, 앱 2.7.0 이상.

**켜기/끄기는 표에서 바로**(확인 없음 — 가장 잦고 되돌리기 쉽다). 응답 행을 id로 덧씌우고 필터와 어긋나도 남긴다(§3-4와 같은 규칙). 토스트가 **켜도 기간이 정한다**는 걸 말한다: 노출 중이면 "지금부터 앱을 여는 사람에게", 예정이면 "{시작}부터", 종료면 "기간이 끝나 보이지 않아요". 끄기는 "앱을 새로 여는 사람부터" — 앱은 세션당 한 번 묻는다. **삭제는 확인 다이얼로그**(노출 중이면 그 사실 + "멈추기만 할 거면 끄기를") → soft delete → 재조회.

**작성·수정** — 왼쪽 폼(640) + 오른쪽 **폰 미리보기**(1280 미만이면 폼 아래로). 미리보기는 앱 `EventPopupCard`와 **같은 수치를 논리 px로 그리고 통째로 줄인다**(390×844 · 딤 55% · 카드 좌우 24·라운드 24·최대 400 · 이미지 4:5 cover · 옐로 필 최소 52·17pt 굵게 · 하단 \[오늘 하루 보지 않기\] | \[닫기\], hideOption NONE이면 \[닫기\]만, 필이 없으면 위 가는 선). 그래서 4:5가 아닌 이미지는 앱에서 잘리는 그대로 잘려 보이고, 긴 버튼 문구는 앱처럼 글자가 줄어든다(FittedBox scaleDown). 하단 고정 문구는 **팝업 언어로**(앱 ARB ko·en·ja).

| 묶음 | 칸 |
|---|---|
| 기본 | 관리용 이름(100자 — 앱에 안 나간다) |
| 이미지 | 파일(JPG·PNG · 10MB · 4:5 권장 — **고르는 즉시** presign → S3 PUT, 끌어다 놓기 가능, 비율이 1% 넘게 어긋나면 "앱에서 잘려요" 안내) · 대체 문구(필수 500자 — 화면 읽기용) |
| 버튼·링크 | 버튼 문구(선택 50자 — 비면 이미지만) · 링크(**https만**) · 여는 방식(앱 안 브라우저 / 외부 브라우저) |
| 누구에게·언제 | 대상(전체 / 선생님 계정 / 개인 계정 — 가입 때 고른 계정 유형, 모임 역할과 무관) · 언어(ko·en·ja — 그 밖의 언어는 한국어 팝업) · 시작·끝(**KST** `datetime-local` — 브라우저 시간대와 무관하게 `+09:00`을 붙여 보낸다) · 우선순위(정수) · 최소 앱 버전(선택 `2.7.0` 꼴) · \[오늘 하루 보지 않기\] 버튼 보이기 · 켜 두기 |

**저장 전 검사는 BE와 같은 규칙**(`admin/lib/promotion.ts` — 목 핸들러도 같은 파일): BE는 링크·기간·버전·이미지 위반을 `POPUP400` 하나로 뭉뚱그려 주므로 화면이 칸마다 먼저 말한다. https 판정은 BE `java.net.URI`가 브라우저 `URL`보다 엄격한 차이(공백·`{}`·깨진 `%`·`https:host` 꼴)까지 먼저 막고, http는 "https로 바꿔 주세요"로 따로 안내한다. 오류는 칸을 떠났거나 저장을 눌렀을 때만 보이고, 막힌 저장은 **첫 오류 칸으로 스크롤·포커스**한다(긴 폼에서 \[만들기\]가 반응 없는 버튼처럼 읽히지 않게). 수정에서 손대지 않은 시각은 원본 그대로 보낸다(입력칸이 분 단위라 23:59:59가 깎인다).

**안내 상자**(폼 맨 위 — 경고가 아니라 안내라 옅은 치즈 면): 앱 2.7.0 이상에서만 보여요 · 링크를 연 사람에게는 기간이 끝날 때까지 다시 안 떠요(앱 CHMO-927 숨김 규칙) · 구독·이용권을 웹 결제로 안내하는 링크는 스토어 정책 위반이에요 · (수정만) 내용을 고쳐도 이미 '오늘 하루 보지 않기'를 누른 사람에게는 오늘 안 보여요, 다시 보이게 하려면 새 팝업으로 — **\[복제해서 새로 만들기\]** 링크(popupId가 유지되는 수정의 한계를 그 자리에서 푸는 문).

**저장 후** 목록으로 돌아가 토스트(navigate state — 한 번 띄우고 지운다). `POPUP404`(다른 관리자가 지움)·`POPUP400`(대개 이미지 업로드 만료·누락)은 폼 아래 한 줄로 받는다.

### 3-7. 혜택 푸시 (CHMO-928 — BE CHMO-926 B절)

`/admin/push`(사이드바 `알림·홍보`). Firebase 콘솔에서 손으로 보내던 혜택·이벤트 알림(앱 release-guide §10)을 대신한다. **법 요건은 서버가 강제한다**(정보통신망법 제50조 — `(광고)` 접두사 · 본문 끝 전송자·수신 거부 문구 · KST 21:00~08:00 금지). 화면은 같은 규칙을 **보내기 전에** 돌려 최종 모습을 보여 주고 야간을 막는다.

**왼쪽 — 작성·발송**: ① 보낼 내용 — 제목(100자 · "(광고)는 자동") · 본문(1,000자 · "수신 거부 문구는 자동") · 링크(선택 · https · 누르면 **외부 브라우저**, 비우면 앱만 — 앱 착지 규칙 CHMO-874). 한글은 3바이트라 1,000자보다 **페이로드 1,800바이트**(자동 문구·data 포함 — BE와 같은 계산)에 먼저 닿아 그때만 크기를 말한다. ② 테스트 발송 — 사용자 ID(기본값 **내 계정** — outletContext `adminUserId`) + \[테스트 발송\]. 토픽을 거치지 않고 그 사용자 기기로만, 동의·푸시 허용·야간 제한은 똑같이 적용(조건이 안 맞으면 `CAMPAIGN400` → "기기가 없거나 수신 동의를 안 했어요"). ③ 보내기 — \[지금 보내기 | 예약하기\] + 예약 시각(KST). 지금이 야간이면 \[지금 보내기\]가 잠기고 **\[다음 08:00으로 예약하기\]**가 선다(시계는 30초마다 다시 본다 — 화면을 연 채 21시를 넘기면 스스로 잠긴다). 예약은 과거·야간 시각을 칸 아래에서 막는다.

**오른쪽 — 받는 사람·미리보기**: 동의자 N명 · 기기 M대(MARKETING 현재 버전 동의 ∧ 푸시 허용 · 기기 없는 적격자도 사람 수엔 든다 · 실제 토픽 구독과 잠시 다를 수 있다) + **"지금 {운영/스테이징/목} 서버예요 · 스테이징 어드민에서 보내면 스테이징 기기에만 가요"**(토픽은 서버 환경 설정이 정한다 — 빌드 설정 `VITE_API_ORIGIN`·`VITE_ENABLE_MSW`로 판별). 아래 잠금 화면 배너 꼴 미리보기는 **서버가 붙인 뒤의 최종본**이고, 붙는 부분(`(광고)`·수신 거부 문구)을 옅은 치즈로 칠해 운영자가 쓴 글과 가른다.

**확인 다이얼로그(전체 발송)** — 열리는 순간 **대상 수를 다시 센다**(그 전엔 확정 버튼이 잠긴다 — 낡은 수를 보고 누르지 않게) → "{서버} 서버 · 지금 기준 동의자 N명 · 기기 M대에게 가요" · 최종 제목 · 즉시면 "보낸 뒤에는 취소할 수 없어요" / 예약이면 "보내기 전까지 이력에서 취소할 수 있어요 · 받는 사람은 보내는 시점의 동의자". 성공하면 작성칸을 비운다(같은 글을 두 번 보내지 않게 — 테스트 대상은 남긴다).

**Idempotency-Key** — 발송 POST·테스트 POST 둘 다 필수(UUID). **같은 발송의 재시도에만 같은 키**: 직전 시도의 본문 지문이 같으면 키를 재사용하고(네트워크 재시도 = 같은 결과), 본문이 바뀌거나 성공하면 새 키다(같은 키·다른 본문은 `CAMPAIGN409`). 테스트와 전체는 키를 따로 쓴다. 규칙은 `promotion.ts createIdempotencyKeeper`.

**발송 이력**(아래 전폭) — 접수 · 내용(최종 제목 + 본문 첫 줄 · 링크 호스트) · 대상(`동의자 전체` / `테스트 · #id (나)`) · 보낸·보낼 시각 · 상태 · 작성자(`#id (나)` — 응답엔 닉네임이 없다) · \[예약 취소\](SCHEDULED만, 확인 다이얼로그 — 닫기 라벨이 `그대로 두기`인 건 \[취소\]\[예약 취소\]가 나란히 서면 어느 쪽이 무엇을 취소하는지 안 읽혀서다). 상태 배지: 예약됨 갈색 · 대기 중·보내는 중 주황 · 보냄 초록 · **실패·일부 실패·결과 확인 필요는 붉은색**(자동 재발송이 없어 사람이 안 보면 묻힌다) + 실패 사유 한 줄(FCM 설정 없음 · 받을 기기 없음 · 야간이 돼 못 보냄 …). **202 접수는 발송 성공이 아니라** 결과가 날 때까지(대기 중·보내는 중·만기 지난 예약) 이력을 5초마다 다시 읽는다(BE 디스패처 주기). 예약 취소 `CAMPAIGN409`(디스패처가 먼저 집었다)는 안내 후 재조회.

**목** — 실 BE의 5초 디스패처 대신 조회할 때 정산한다(즉시 발송은 3초 뒤 만기로 접수 — '대기 중'이 잠깐 보이고 폴링이 '보냄'으로 바꾸는 것까지 탄다). 시드: 팝업 4종(조회 시각 기준 상대 기간 — 탭 넷이 언제나 찬다)·발송 이력 4건(예약·보냄·테스트·실패) · 수신 대상(동의만 있고 기기 없는 사람 · 기기만 있고 동의 없는 사람을 섞어 두 수의 차이가 보이게).

### 3-8. 사용자 · 무료 사진 장수 (CHMO-931 — BE CHMO-912)

`/admin/users`(검색) · `/admin/users/:userId`(상세). 사이드바 `사용자`(기관 구독 아래·모임 위). 업로드 과금(CHMO-912)이 운영에 들어가면서 운영자가 "이 사용자에게 분석(업로드)할 수 있는 장수를 더 준다"를 할 자리가 필요했다 — 그 전엔 BE 개발자의 curl뿐이었다.

**검색** — 닉네임 부분 일치(대소문자 무시) 또는 userId 정확 일치(`GET /admin/users?query=`). 검색어가 비면 **최근 가입 순 전체**라 "방금 가입한 사람"도 여기서 본다. 열: 사용자(닉네임 · `#userId`) · 계정 유형(개인/기관 — 가입 때 고른 탭이지 모임 역할이 아니다). BE가 커서 목록이라 페이지 버튼 대신 \[더 보기\](`AdminLoadMore` · 커서 훅 `useCursorList`). 닉네임은 소셜 가입이라 여럿이 같을 수 있어 "신고·문의 화면의 `#userId`를 넣으면 그 계정만 나온다"를 한 줄로 말한다.

**상세 — 요약 머리**(CHMO-932 — BE A-5 `GET /admin/users/{id}`): 닉네임 `#id` + 계정 유형 칩(개인/기관) + 어드민 권한 칩(role ADMIN일 때만) · 가입일 · 로그인 수단(소셜 종류 — PIN 계정은 'PIN') · 속한 모임 수 + **모임 칩 목록**(`모임 #45 · 비즈니스 · 관리자` (승인 대기) → 모임 상세. 역할 라벨은 모임 유형을 본다 — 일반은 '멤버'). 종전(CHMO-931)엔 요약 API가 없어 검색 API를 `query=<id>`로 다시 불러 id가 같은 행을 집었다(닉네임에 그 숫자가 섞인 남까지 걸렸다).

**상세 — 장수 카드** — 잔액(큰 수) + \[장수 지급\] \[회수\] + 장부 표(시각 · 사유 · 증감 · 잔액). 사유는 가입 지급 / 전환 지급(적용 시각 전 가입자 500장) / 일일 적립 / 업로드 차감(`모임 #N · 모임명 › 이벤트명` — 이름은 **지금 값**이라 지워졌으면 `(지워진 모임)`) / 운영자 조정(메모가 그대로 붙는다). 증감은 +초록 · −붉은색.

**장수 조정 다이얼로그**(`CreditAdjustDialog`) — 지급/회수 세그먼트 · 장수 · 메모(필수 500자 — 장부에 그대로 남는다) → `POST …/credit-adjustments {delta, memo}`(회수는 음수). 규칙은 `admin/lib/billing.ts`가 BE와 같게 먼저 돌린다: delta ≠ 0 · 메모 필수 · **회수는 잔액을 넘길 수 없다**(`CreditAccount.adjust`가 음수를 `CREDIT409`로 거절 — 화면이 먼저 막고, 다른 관리자와 겹쳐 서버가 거절하면 장수 칸 아래에서 다시 말한다) · 지급은 500 상한을 넘겨도 된다(스펙 3.5). "반영 뒤 잔액 N장"을 칸 아래에 미리 보여 준다. 성공 → 잔액·장부 재조회 + 토스트. **`Idempotency-Key`**(CHMO-932 — ADR 045): 다이얼로그를 열 때 UUID를 한 번 만들어 재시도에만 재사용한다 — 응답을 못 받고 다시 눌러도 서버가 두 번 지급하지 않는다(장수 조정·기간 등록·패스 지급 셋 공통, 선택 헤더라 없으면 종전처럼 매번 실행). 같은 키 다른 내용은 ADMIN409(`ADMIN_REQUEST_CONFLICT`) — 실제로 오면 키 재사용 결함이라 "창을 닫고 다시 열어 주세요". 전송 중 버튼 잠금은 그대로 둔다(키는 재시도 안전망이지 UI 잠금의 대체가 아니다).

**장수 기능이 서버에 안 켜졌으면**(`credit.enforcement-starts-at` 비어 있음 → 조회·조정 전부 `BILLING503`) 오류가 아니라 **안내 상자**다 — "앱 2.6.0 공개 뒤 설정을 켜면 이 카드가 살아난다". 조회 자체가 장부 계정을 지연 생성한다(BE `CreditAccountStore.lock` — 한 번도 안 쓴 사용자도 초기 지급 행 하나를 갖고 온다).

**상세 — 기관 이용 기간 구획(기관 계정만)** — 지금 상태(배지 + 종료일 · 유예 종료) + \[이용 기간 등록\](§3-9 다이얼로그) + **이력 표**(CHMO-932 — BE A-4 `GET /admin/organizations/{id}/subscription`, **무효화분 포함** 최신순): 이용 기간 · 출처 배지(**가입 체험** — BE CHMO-940이 넣은 기간, `adminId` null / 운영자 등록) · 입금(금액 · 입금일 · 입금자 · 세금계산서)+메모 · 등록(시각 · 관리자 `#id` 또는 `서버(체험)`) · \[무효화\]/`무효화됨`(취소선). 어느 기간이든 무효화할 수 있다(확인 다이얼로그 뒤 `DELETE …/organization-subscription-periods/{periodId}` → 이력 재조회) — 종전(CHMO-931)엔 이력 API가 없어 이번 세션에 등록한 기간만 되돌렸다. 구독 행이 없는 기관은 404가 아니라 빈 이력 + 차단(BE 정책). 기관 계정도 개인 범위 모임에 들어가 업로드하면 장수를 쓰므로 장수 카드는 누구에게나 있다. 이력은 기관 계정일 때만 부른다(개인 계정에 부르면 VALID400 — useApi 키를 null로 둬 요청 자체가 안 나간다).

### 3-9. 기관 구독 (CHMO-931 — BE CHMO-912)

`/admin/organizations`. 사이드바 `기관 구독`(기관 문의 바로 아래 — 개통의 다음 일). 기관은 계좌이체 월 정액이라 결제가 서버에 자동으로 들어오지 않는다 — 입금을 확인한 운영자가 여기서 기간을 더한다.

| 컬럼 | 비고 |
|---|---|
| 기관 계정 | 닉네임 · `#userId`(지워진 계정은 `(지워진 계정)`). 행 클릭 → 사용자 상세 |
| 이용 상태 | **이용 중**(초록) / **유예 기간**(주황 — 종료 뒤 7일, 업로드는 된다) / **차단**(붉은색 — 새 업로드 `BILLING403`). 요청 시각 기준으로 서버가 계산(`InstitutionAccessResolver`) |
| 이용 종료일 | `accessUntil`(배타적 끝 시각)을 **1ms 전의 KST 날짜**로 보여 "그 날까지"로 읽는다(`accessUntilToKstDate`) |
| 유예 종료 | `graceEndsAt` |
| \[이용 기간 등록\] | 셀 여백까지 행 클릭을 막는다(팝업 스위치 칸과 같은 규칙) |

**기간 등록 다이얼로그**(`SubscriptionPeriodDialog` — 폼 상태 `hooks/useSubscriptionPeriodForm` · 칸 `SubscriptionPeriodFields`, 개통 창과 공용) — 이용 시작일·종료일(`type="date"` · **KST** · 종료일 **포함**: 서버엔 다음 날 0시 `+09:00`를 보낸다, 기본값 오늘~30일 뒤) · 입금액(원, 0 허용 = 무상) · 입금일(기본 오늘) · 입금자명(필수 100자) · 세금계산서 번호(선택) · 메모(선택 500자) → `POST /admin/organizations/{userId}/subscription-periods`(201). **등록은 더하기만**이다 — 기간이 겹쳐도 되고 접근 상태는 무효화되지 않은 기간 중 가장 늦은 종료로 계산되므로 "연장"도 새 기간 등록이다. 검증은 BE DTO·등록기와 같은 규칙을 화면이 먼저 돌린다(`billing.ts validateSubscriptionPeriod` — 종료<시작·음수 금액·빈 입금자명), 서버가 거절하는 건 실질 "기관 계정이 아닙니다"(VALID400)뿐이라 폼 아래 한 줄로 받는다. 성공 → 목록 재조회(차단 → 이용 중으로 바뀐다) + 토스트("~까지").

**이 목록에 없는 기관** — 구독 행은 첫 기간이 생길 때 만들어진다. BE CHMO-940(가입 체험 14일 자동)이 기관 계정 생성 때 구독 행을 만들므로 이제 거의 모든 기관이 여기 보이고, 체험 전 가입자(백필로 대부분 해소)만 기관 문의 개통 때 함께 등록하거나(§3-4) 사용자 검색에서 찾아 등록한다 — 목록 위 한 줄이 그렇게 안내한다. 기간 **이력**·아무 기간이나 무효화는 행 클릭 → 사용자 상세(§3-8, CHMO-932).

**목** — `handlers/adminBilling.ts`. 검증 순서는 BE 유스케이스 그대로(가드 → Bean Validation(VALID400) → 설정 → 대상(USER404) → 도메인(CREDIT409 · 기관 계정 VALID400)), 커서 `size`는 BE처럼 1~50으로 **접는다**(400이 아니다 — 모임 목록과 다르다). `DbUser.accountType` 신설(기관 문의를 낸 시드 계정 2·3·5·6·7 = 기관), 장부 시드는 이현정(1) 한 사람(전환 지급 500 → 업로드 −32 → 일일 적립 ×2 → 운영자 조정 +100 = 588장)이고 나머지는 조회 때 지연 생성. 구독 시드는 **지금 기준 상대 시각**(팝업과 같은 이유)으로 서연맘 이용 중 · 지호네 유예 · 박수민 차단 · 김지은은 기간 없음(개통 때 등록 흐름용).

### 3-10. 운영 설정 (CHMO-957 — BE CHMO-958)

**구현 상태(2026-10-19)**: `/admin/operation-settings`에 앱 버전·스토어, 무료 사진·차감, 기관 이용, 출석 알림, 안전 상한·바로가기, 변경 이력을 제공한다. BE [PR #329](https://github.com/CheeseMoa/CheeseMoa-BE/pull/329)의 DTO·정책·컨트롤러 및 명세를 대조했다. 로컬 MSW 화면 검증이며 실 BE 응답 채집·저장 연동은 미검증이다.

**저장·복원(2026-10-19 사용자 변경 지시)**: 보안 강화는 CHMO-934에서 나중에 진행한다. FE의 추가 인증 대기 잠금을 제거해 기존 관리자 세션으로 저장·복원을 요청한다. 서버 권한 검사·revision 충돌·사유·입력 검증·쓰기 비활성 응답 처리는 유지한다. 실제 서버 저장·복원은 개발 환경에서 변경 전 값을 기록하고 비활성 알림 문구를 잠시 변경한 뒤 원상 복원하여 검증한다. 운영 설정·과금·잔액·전체 발송은 검증으로 변경하지 않는다.

- 현재 서버 값과 revision·변경 시각을 조회하며 고정 기본값을 사용하지 않는다. 조회 실패는 재시도한다.
- 한 구분씩 편집한다. 구분 이동·다른 화면 이동·새로고침 시 미저장 변경을 알린다. 저장·복원은 전후 값과 사유(공백 제외 1~500자)·적용 범위 확인을 거친다.
- 앱: iOS·Android 최소 버전과 스토어 URL. 선행 0 없는 `major.minor.patch`를 받으며 한 플랫폼의 변경만 보내 다른 값을 보존한다. URL은 HTTPS, 플랫폼별 `apps.apple.com`/`play.google.com`, 기본 포트/443, 경로 필수, 사용자 정보·fragment 금지. 비우면 null로 삭제하고 앱 기본 URL을 사용한다. 스토어 실제 공개 여부와 설치 가능 상태를 직접 확인하고 사유에 근거를 남긴다.
- 무료 사진: 신규 가입·기존 가입자의 최초 장부 지급량은 0~10,000장 정수. 이미 존재하는 잔액·원장은 재설정하지 않는다. 출석 적립 상한은 관리자 지급 상한이 아니며 기존 잔액을 삭감하지 않는다. **일일 지급량·출석 상한은 APP 고정 문구/게이지 후속 전까지 편집 및 해당 값이 달라지는 복원을 제한**한다. 서버 호환 안내도 표시한다.
- 차감: KST 입력·표시, 서버에는 UTC Instant. 비우면 null(비활성화)로 저장하며 장수·출석 API가 비활성화되고 업로드 차감 판정은 DISABLED가 된다. 미래 시작일이라도 출석 API는 사용할 수 있다. 푸시는 차감 시작 이후이며 일일 지급량 양수일 때 처리된다. **고정 `migrationCutoffAt`은 별도 조회 전용**이며 차감 시작일 수정·비활성화·복원으로 바뀌지 않는다.
- 기관: 체험·유예 0~365 정수 일. ISO Duration을 일수로 표시하고 변경 시 ISO 기간을 보낸다. 체험 변경은 신규 부여에만 적용하며 기존 이력은 바꾸지 않는다. 유예는 실제 이용 종료일 + 현재 기간으로 즉시 판정하여 기존 만료 기관 접근에도 영향을 준다.
- 출석: 기존 GET/PUT 설정 API·날짜별 statistics API를 사용한다. KST 08:00~20:59, ko/en/ja 제목 1~100자·본문 1~1,000자 및 자동 광고 고지 포함 UTF-8 페이로드를 검증한다. 언어별 최종 광고 문구를 미리 보여준다. 시각이 지난 뒤 21시 전에 활성화하면 당일 다음 주기에 발송될 수 있음을 확인한다. FCM 수락·발송 시도 후 활동 집계는 실제 수신·탭 전환·인과관계와 구분한다.
- 저장 중 동기 중복 요청을 막고 실패 시 입력을 보존한다. 성공 후 재조회 실패는 “저장 완료·재조회 필요”로 구분하며 다시 저장하지 못하게 한다. revision 충돌은 자동 재시도하지 않고 입력을 보존한다. 운영자가 내용을 기록한 뒤 명시적으로 최신 값을 다시 조회해 검토한다.
- 이력: 변경자·시각·사유·revision·적용 범위·전후 값·복원 원본을 조회한다. BEFORE/AFTER 복원은 현재 revision과 새 사유를 보내는 새 변경이다. 고정 가입자 기준일과 이미 지급·발송·부여한 효과를 되돌리지 않는다.
- 업로드 요청당/이벤트당/모임당 안전 상한은 서버 조회값만 표시한다. 사용자 장수, 기관 기간, 모임 패스, 팝업, 혜택 푸시는 기존 화면으로 연결한다.

**코드리뷰 보완(2026-10-19)**: 편집 기준은 화면 진입마다 새로 조회하고 페이지 전용 캐시는 이탈 시 폐기한다. 저장 후 조회 실패의 401도 기존 세션 만료 흐름으로 전달하며 쓰기를 반복하지 않는다. 저장 중 새로고침도 이탈 경고를 적용한다. 존재하지 않는 날짜의 자동 보정을 막는다. 이력 첫 페이지가 바뀌면 이전 커서 목록을 폐기한다.

**실 BE 검증 대기**: 관리자 조회·출석 ETag 노출·통계·이력, 비관리자/세션 만료·충돌·저장 실패·복원 및 추후 CHMO-934의 추가 인증, 저장 후 무인증 `GET /app/config` 일치를 로컬 BE 또는 스테이징에서 확인한다. 운영 설정·과금·잔액·최소 버전이나 실제 전체 발송은 테스트로 변경하지 않는다.

**확정된 정책** (BE 스펙 정책 결정 표에서 발췌)

- 경로는 `/admin/groups` — 티켓 초안의 `spaces`는 내부 명칭이 샌 표기라 폐기(직렬화 경계 밖은 group/event).
- 멤버 수 = ACTIVE만(서비스 화면과 같은 규칙 — 상세 멤버 행 수와 다를 수 있고 `status`가 설명한다). 사진 수 = 앨범 매핑(AlbumPhoto) distinct — 분류를 거친 사진만. 총 사진(stats)은 photo 행 count.
- **모임 이름은 어드민 응답 3곳(stats.recentGroups·목록·상세) 어디에도 없다**(BE CHMO-668 / PR #203, 2026-08-11) — 어드민은 모임을 groupId로만 식별한다. 이벤트 이름·멤버 닉네임·생성자 닉네임은 모임 이름이 아니라 존치. 화면은 전부 `모임 #{groupId}` 표기(FE `admin/lib/format.ts` `groupLabel` 단일 원천, CHMO-670).
- 정렬 화이트리스트 `lastUploadedAt`·`photoCount`·`createdAt`·`name` × `asc`·`desc`(기본 **`lastUploadedAt,desc`** — CHMO-932에서 바뀜, 사진 없는 모임은 방향과 무관하게 맨 뒤·동률 `createdAt desc, groupId desc`). 집계 컬럼 정렬은 CHMO-378의 "1차 제외"가 해제된 것(저장 컬럼 없이 요청마다 집계 — 느려지면 `last_uploaded_at` 컬럼 후속). `size`는 1~100. 검색 `q`·정렬 `name`은 BE가 계속 받지만(값만 걷고 동작은 유지) **FE는 보내지 않는다**(§3-2).
- **활동 지표 제외 계정**(CHMO-932): `activeGroups`·`uploaders`·`recentUploads`만 서버 설정 `ADMIN_STATS_EXCLUDED_USER_IDS`(Grafana CHMO-846과 같은 목록) 계정이 올린 사진을 뺀다. 기존 필드(totals·new*)의 뜻은 바꾸지 않았다. 업로더 없는 옛 사진(CHMO-805 이전)은 제외 대상이 아니고 `uploaders`엔 안 센다.
- 집계 캐시는 안 넣는다(현 규모 count는 ms 단위 — 느려지면 그때 측정).
- 응답에 시크릿 4종(joinKey·모임 비밀번호·공유 토큰·학부모 공유 비밀번호) 없음(§3-3, AC-6).

### CHMO-957 출석 설정 실서버 회귀 수정 (2026-10-19)

개발 웹에서 staging-api의 출석 설정 GET이 HTTP 200·`ETag: W/"0"`·`Access-Control-Expose-Headers: X-Request-Id, ETag`로 응답하는 것을 Chrome Network에서 확인했다. FE가 강한 태그만 허용하여 정상 응답을 거부했고, 일반 Error가 useApi에서 NETWORK_ERROR로 변환됐다. 이 API의 숫자 revision 태그는 강한/약한 형태 모두 읽되, BE SettingsWriteHeaders 계약에 맞춰 PUT에는 `If-Match: "revision"`을 전송한다. 헤더 누락·잘못된 숫자 태그는 FE 로컬 오류 `INVALID_SETTINGS_RESPONSE`로 구분하고, 실패 뒤 계속 조회 중이라고 표시하지 않는다. 본문은 인증정보 없는 실응답 픽스처로 보관한다. 이 수정은 쓰기 잠금이나 보안 정책을 변경하지 않는다.
