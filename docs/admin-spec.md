## 1. 목적

운영 중 나오는 질문에 DB 직접 조회 없이 답하기 위한 백오피스.

- "가입자·모임이 얼마나 늘고 있나"
- "어느 유치원이 실제로 쓰고 있나"
- "이 모임 상태가 지금 어떤가" (문의 대응)

**범위 밖**: 기관 관리자용 모임 내 관리, 결제/요금제, 고객 문의 시스템.

## 2. 확정 결정 3가지

### 2-1. 배포 위치 — 같은 리포 `/admin` 라우트

**판단 근거**

- 모바일 프레임(`PhoneShell`)은 라우터가 아니라 **페이지마다 개별로 두른다**(`src/router.tsx`, 21개 페이지가 각자 import). `/admin` 페이지는 안 두르면 그만이라 "모바일 셸과 섞인다"는 문제가 실제로는 없다.
- 재사용되는 것: `src/api/client.ts`(응답 봉투 언랩 + **401 리프레시 토큰 회전·in-flight 공유**), `src/api/errors.ts`, `src/lib/auth.ts`, `useApi`/`useMutation`, 타입 계약. 특히 리프레시 로직은 미묘해 다시 짜면 버그가 나기 쉽다.
- 배포·CI가 1개로 유지된다(Vercel 프로젝트 1개, `vercel.json`이 `/api/v1/*`를 실 BE로 rewrite).

**대가와 대응**

| 대가 | 대응 |
|---|---|
| 번들 증가 | 라우트를 `lazy()`로 분리(`/dev/components` 선례) — `/admin` 진입자만 받는다 |
| 학부모 뷰어와 같은 도메인 | 1차는 조회 전용이라 수용. 쓰기 액션이 들어올 때 재검토 |

### 2-2. 나중에 별도 리포로 격리하기 위한 규칙 3개 (지금부터 지킨다)

이 규칙을 지키면 격리는 "폴더 옮기고 Vercel 프로젝트 하나 파기"로 끝난다. 안 지키면 실 뽑듯 뜯어내야 한다.

1. **관리자 코드는 `src/admin/` 한 폴더에만.** 서비스 코드가 관리자 코드를 import하지 않는다(의존 방향 한쪽).
2. **공유는 바닥 인프라뿐** — `api/client.ts`·`lib/auth.ts` 등. 화면 컴포넌트는 서로 쓰지 않는다.
3. **BE 경로를 처음부터 `/admin/*`으로 분리.** 프론트를 떼어내도 BE는 그대로 둔다.

### 2-3. 인증 — 유저에 관리자 역할(role) 부여

**핵심 원칙**

> **기존 서비스 API는 role을 쳐다보지 않는다.** 관리자여도 자기가 멤버가 아닌 모임은 일반 화면에서 볼 수 없다. 전체 데이터는 `/admin/*` 전용 API에서만 보인다.

- role은 **더하는 것이지 바꾸는 것이 아니다** — 관리자 계정도 평범한 유저로서 모임 생성·업로드·검수·공개를 그대로 한다(테스트 계정으로 겸용 가능).
- 초기 관리자 지정은 DB 직접 변경으로 충분하다. ⚠ **계정 생성은 반드시 signup API로** — BE가 PIN을 BCrypt 해시로 저장·비교하므로 DB에 평문 행을 직접 넣으면 로그인이 영원히 실패한다(2026-08-04 실측). role 칼럼만 DB에서 바꾼다.
- 기본값은 일반 유저 — 기존 행은 마이그레이션 영향이 없다.
- 소셜 로그인 전환(CHMO-359·363) 중이라 **인증 체계를 하나 더 만들지 않는다**. 별도 관리자 계정 체계는 규모가 커진 뒤 재검토하며, 그때 바꾸는 것은 `/admin/*` 앞의 인가 검사뿐이고 서비스 API는 손대지 않는다.
- **진입 플로우(CHMO-594)** — 진입점은 URL `/admin`뿐이고 서비스 화면엔 버튼이 없다(서비스 API가 role을 안 보므로 보여줄 근거도 없다). 비로그인·세션 만료로 `/admin`에 오면 모바일 랜딩으로 보내지 않고 **어드민 셸 안 데스크탑 로그인 카드**(같은 계정·같은 `POST /auth/login` — 인증 체계 추가 아님)를 그 자리에 그리고, 성공하면 이동 없이 게이트를 재판정한다. 소셜 계정 관리자는 카드의 링크로 01 랜딩에 다녀온다(returnTo=/admin). 비관리자 차단 화면엔 [다른 계정으로 로그인](토큰 폐기 → 카드 복귀). 가입 동의 게이트(CHMO-479)는 어드민 로그인에 태우지 않는다. 로그아웃은 사이드바 하단 프로필 곁 [로그아웃](CHMO-595 — 서버 refreshToken 무효화 후 로컬 삭제, 실패에도 로컬 로그아웃 진행 → 로그인 카드 복귀).

### 3-4. 기관 문의 (CHMO-811 — 어드민의 첫 쓰기 화면)

`/admin/inquiries`. 앱이 \[개인 | 유치원·기관\]으로 갈리면서(CHMO-803) 기관 계정은 도입 문의를 낸 뒤 **팀이 개통할 때까지 승인 대기 화면에 머문다**(CHMO-809). 그 개통을 지금까지 BE 개발자의 SQL이 하고 있었고, 이 화면이 그 자리를 대신한다. §6의 "B2B 기관 등록 검수"가 앞당겨진 것이다.

**필터 탭** — 진행 중(기본) / 개통 / 종료 / 전체. 각각 `status` 쿼리 값(`RECEIVED,CONTACTED` / `ONBOARDED` / `CLOSED` / `ALL`)이고, 생략 시 BE 기본값이 곧 '진행 중'이다.

| 컬럼 | 비고 |
|---|---|
| 접수일 | 정렬은 `createdAt,desc` 고정(`sort` 파라미터 없음) |
| 기관 | 기관명 + 유형(유치원·어린이집·학원·기타) · 지역 |
| 담당자 | 이름 + 역할(원장님·선생님·행정) — 역할은 선택 항목이라 `—` 가능 |
| 연락처 | `tel:` 링크. **마스킹하지 않는다** — 팀이 전화하려고 받은 값이고 이 화면은 관리자 전용(CHMO-802 정책) |
| 사용자 | 닉네임 · `#userId` · 소셜 수단(없으면 `PIN`) |
| 상태 | 접수됨 / 연락 완료 / 개통 / 종료 |
| 갱신일 | 마지막 전이 시각(`updatedAt`) |
| 상태 변경 | 주 동작 버튼 + `⋯` (아래) |

**전이 — 규칙이 없다.** 어느 상태에서 어느 상태로든 갈 수 있고 같은 값 재요청도 에러가 아니다(BE CHMO-810 결정: 관리자가 잘못 누른 값을 화면에서 직접 고칠 수 있어야 한다). 그래서 **개통·종료 행에도 액션이 뜬다** — 숨기면 실수로 누른 `CLOSED`를 되돌릴 방법이 UI에 없다. 초안의 `INQUIRY400`(이미 전이됨)은 폐기돼 존재하지 않는다.

**다만 셋을 나란히 두지는 않는다.** 같은 무게의 버튼 셋은 "지금 뭘 해야 하는지"를 지우고, 상태 이름이 적힌 버튼(`접수됨`)은 현재 상태를 말하는지 누르면 그리로 간다는 건지 읽히지 않는다. 그래서 **라벨은 동사**이고, 주 동작 하나만 버튼으로 세우고 나머지는 `⋯`로 접는다.

| 현재 상태 | 주 버튼 | `⋯` |
|---|---|---|
| 접수됨 | \[개통하기\] | 연락 완료로 표시 · 종료하기 |
| 연락 완료 | \[개통하기\] | 접수됨으로 되돌리기 · 종료하기 |
| 개통 | 없음 | **개통을 취소하고** → 접수됨으로 · 연락 완료로 · 종료로 |
| 종료 | 없음 | 접수됨으로 되돌리기 · 연락 완료로 표시 · 개통하기 |

`개통` 행에 주 버튼이 없는 이유는 셋 다 결과가 같아서다 — 어느 상태로 보내든 그 계정은 승인 대기 화면으로 돌아간다. 목적지는 셋 다 열어 두되(되돌릴 곳을 서버가 기억하지 않는다) `개통을 취소하고`라는 한 제목 아래 묶어, 무슨 일이 일어나는지를 항목마다 되풀이하지 않는다.

**상태의 뜻은 화면이 한 줄로 말한다** — 목록 위 "접수됨 · 연락 완료는 아직 진행 중이에요. **개통**하면 그 계정이 앱에서 모임을 만들고 사진을 올릴 수 있어요." 상태 이름만으로는 무엇이 달라지는지 알 수 없다.

| 확인 모달 | 언제 | 요지 |
|---|---|---|
| 개통 | `→ ONBOARDED` | "개통하면 이 사용자가 앱에서 모임을 만들고 사진을 올릴 수 있어요" + 사용자 쪽 다음 동작 |
| 개통 취소 | **`ONBOARDED`에서 나가는 전이 전부** | "승인 대기 화면으로 돌아가요. **모임과 사진은 그대로 남고**, 다시 개통하면 이어서 쓸 수 있어요" |
| 종료 | `→ CLOSED` | "다시 진행하려면 사용자가 문의를 새로 내야 해요" |

개통 취소를 목적지(`CLOSED`)가 아니라 **출발지**(`ONBOARDED`)로 판정하는 이유: 사용자 화면에서는 `CLOSED`로 보내든 `RECEIVED`로 되돌리든 똑같이 승인 대기로 돌아간다. 목적지로 가르면 가장 파괴적으로 보이는 되돌리기만 확인 없이 나간다. 나머지(연락 완료 표시, 종료분 되돌리기)는 사용자 화면을 바꾸지 않는 운영 메모라 바로 나간다.

**전이 후** — 성공 토스트 + **그 행만 제자리 갱신**(PATCH 응답이 목록 행과 같은 형태라 재조회가 없다). 필터와 어긋나게 된 행도 그 자리에 남긴다: 방금 누른 행이 사라지면 잘못 누른 값을 되돌릴 대상이 화면에서 없어진다. 다음 조회(탭·페이지 이동·\[새로고침\])에서 빠진다.

**실패 2종** — `INQUIRY404`(없는 문의)·`INQUIRY409`(되돌리기 충돌 — 그 사용자에게 진행 중 문의가 이미 있다, CHMO-802의 "진행 중 1건" 제약)는 둘 다 "화면이 든 목록이 낡았다"는 뜻이라 안내 후 목록을 다시 읽는다.

**대시보드 카드** — "대기 중 기관 문의 N건"(→ 이 화면). 전용 카운트 API가 없어 목록을 `size=1`로 부르고 봉투 `pageInfo.totalElements`만 읽는다.

**전이 이력은 화면에 없다** — 누가·언제·from/to는 테이블이 아니라 CloudWatch 액세스 로그가 정본이고(BE [ADR 017](https://github.com/CheeseMoa/CheeseMoa-BE/blob/develop/docs/decisions/017-access-log-as-audit-record.md)) 조회 API가 없다. 화면에는 마지막 전이 시각만 둔다.

## 4. API (확정 — BE CHMO-378, 2026-08-04 develop 머지 · 소스 대조)

정본은 BE 리포 `docs/spec/CHMO-378-관리자-조회-API.md`. 전부 `/admin/*` 아래·기존 응답
봉투·숫자 ID 규약이고, 인증은 회원과 같은 JWT(관리자 role 필요 — CHMO-377 가드).

| 용도 | 확정 | 응답 |
|---|---|---|
| 진입 게이트 | `GET /admin/me` | `{userId, nickname, role}` — 관리자 아니면 ADMIN403이라 FE 가드가 이걸로 판정 (CHMO-377) |
| 대시보드 요약 | `GET /admin/stats` | `totals`(users·groups·events·photos) + `last7Days`(newGroups·newEvents·newPhotos) + `recentGroups` 5개 고정(행: groupId·memberCount·createdAt) |
| 모임 목록 | `GET /admin/groups?page&size&q&sort` | 행: groupId·memberCount·eventCount·photoCount·createdAt — **페이지 정보는 봉투의 `pageInfo`**(page·size·hasNext·totalElements·totalPages) |
| 모임 상세 | `GET /admin/groups/{groupId}` | 기본정보(groupId·createdAt·카운트)+생성자 + 멤버 목록(**PENDING 포함**, spaceUserId 오름차순) + 이벤트 목록(eventId 내림차순, publishedAt은 미공개 null) |
| 기관 문의 목록 | `GET /admin/organization-inquiries?page&size&status` | 행: id·status·organizationType/Name·region·contact{Name,Phone,Role}·privacyConsentVersion·userId·userNickname·socialProviders·createdAt·updatedAt. 정렬 `createdAt,desc` 고정 · `status` 기본값 `RECEIVED,CONTACTED`(`ALL` 지원) — BE CHMO-810 |
| 기관 문의 전이 | `PATCH /admin/organization-inquiries/{id}` | 요청 `{status}` · 응답은 **갱신된 행**(목록과 같은 형태). 전이 규칙 없음 — BE CHMO-810 |

**확정된 정책** (BE 스펙 정책 결정 표에서 발췌)

- 경로는 `/admin/groups` — 티켓 초안의 `spaces`는 내부 명칭이 샌 표기라 폐기(직렬화 경계 밖은 group/event).
- 멤버 수 = ACTIVE만(서비스 화면과 같은 규칙 — 상세 멤버 행 수와 다를 수 있고 `status`가 설명한다). 사진 수 = 앨범 매핑(AlbumPhoto) distinct — 분류를 거친 사진만. 총 사진(stats)은 photo 행 count.
- **모임 이름은 어드민 응답 3곳(stats.recentGroups·목록·상세) 어디에도 없다**(BE CHMO-668 / PR #203, 2026-08-11) — 어드민은 모임을 groupId로만 식별한다. 이벤트 이름·멤버 닉네임·생성자 닉네임은 모임 이름이 아니라 존치. 화면은 전부 `모임 #{groupId}` 표기(FE `admin/lib/format.ts` `groupLabel` 단일 원천, CHMO-670).
- 정렬 화이트리스트 `createdAt`·`name` × `asc`·`desc`(기본 `createdAt,desc`) — **집계 컬럼 정렬(§3-2 '사진 많은 순')은 1차 제외**. `size`는 1~100. 검색 `q`·정렬 `name`은 BE가 계속 받지만(값만 걷고 동작은 유지) **FE는 보내지 않는다**(§3-2).
- 집계 캐시는 안 넣는다(현 규모 count는 ms 단위 — 느려지면 그때 측정).
- 응답에 시크릿 4종(joinKey·모임 비밀번호·공유 토큰·학부모 공유 비밀번호) 없음(§3-3, AC-6).

**에러**: 무토큰 `COMMON401` → 비관리자 `ADMIN403`(403 — 2026-08-04 실서버 채집) · 상세 없는 모임 `SPACE404` · 목록 파라미터 검증 실패 `COMMON400` · 기관 문의 `INQUIRY404`(없는 id)·`INQUIRY409`(되돌리기 충돌 — BE CHMO-810, 실서버 채집은 배포 후).
