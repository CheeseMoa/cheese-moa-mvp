## 0. 확정 모델 요약 (모든 화면의 전제)

- **타깃**: 기관(B2B/유치원) 우선.
- **정보구조**: `모임(Group) > 이벤트(Event) > 앨범(Album)`.
- **인증(제작자)**: 닉네임 + 4자리 PIN.
- **권한**: 등급 없음. 로그인한 모임 멤버는 누구나 업로드·검수·공개 가능.
- **모임 진입점 2개(분리)**
  - **선생님 초대** = 로그인 제작자를 모임에 합류시키는 입구. **모임 단위**(모임 비밀번호 + 참여 링크).
  - **학부모 공개** = 무로그인 뷰어(조회·다운로드만). **모임 단위** 공유 링크 + **학부모 전용 비밀번호**(모임 비밀번호와 별개, 생성 시 자동). 비번 입력 후 **공개된 이벤트 목록**에서 선택.
- **공개(publish) 단위**: **이벤트별** (검수 → 공개 요약 → 공개하기). **학부모 접근(공유) 단위**: **모임별**(공개된 이벤트만 목록 노출).
- **BE/AI 미구현**: FE는 [API 명세서](./api-spec.md) 계약에 목 데이터로 개발.

## 1. 디자인 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `--color-primary` | `#F5B82E` | 주요 버튼/강조(치즈 옐로우) |
| `--color-accent` | `#8C5A2B` | 검토완료 테두리/보조 강조(갈색) |
| `--color-warn` | `#E4572E` | 되돌릴 수 없는 동작(삭제 등) + 실패 알림 |
| `--color-bg` | `#FFFDF5` | 페이지 배경 |
| `--color-surface` | `#F3F0E9` | 카드/입력 표면 |
| `--color-text` | `#3A3128` | 본문 텍스트 |
| `--color-muted` | `#9E978C` | 보조 텍스트/플레이스홀더 |
| `--color-border` | `#E6E0D4` | 구분선/기본 테두리 |

- **`warn`(빨강) 사용 규칙(2026-07-29 확정)**: ① 되돌릴 수 없는 동작 — 삭제(모임·이벤트·앨범·사진), 신청 거절, 아이 연결 해제 ② 실제 실패 알림(`role="alert"` 인라인 에러·`ErrorState`·입력 검증). **그 외 안내성 문구에는 쓰지 않는다** — 아직 할 일이 남았다는 안내(14 공개 게이트, 06-U 미선택 사진 고지)는 `heading`, 상태 라벨(09 라이트박스 눈감음·흔들림)은 중립 칩. 빨강을 안내에 쓰면 "내가 뭘 잘못했나"로 읽히고, 정작 삭제 버튼이 같은 색이라 위험 신호가 묽어진다.
- **앨범 카드 테두리 규칙**: 갈색(`accent`) 실선 = 검토완료 · 회색(`border`) 점선 = 미검토. (기준: 앨범 내 미검토 **사진** 유무 — 검토는 사진 단위, `unreviewedPhotoCount`로 판정)
- 상단 상태바(`9:41`)는 디바이스 영역으로 구현 대상 아님.

로그인 진입(01)
 ├─ 계정 생성(01-2) ─┐
 └─ 로그인(01-1) ────┴─▶ 홈/내 모임(02)          ※ returnTo(초대 링크 등)가 있으면 그쪽 우선
                            └─ 첫 로그인 1회 ─▶ 치즈모아 둘러보기(00-T · 홈 위 전체 화면)
                                                  └─ [다 봤어요] / ✕ ─▶ 홈(02)
   ※ 첫 사용 온보딩 슬라이드(00)는 현재 노출하지 않는다(CHMO-504) — 화면은 남아 있고 진입점만 내렸다
홈/내 모임(02)
 ├─ 모임 만들기(03) ─▶ 모임 상세(05)
 ├─ 모임 참여(02-1, 모달) ─▶ 모임 상세(05)
 └─ 모임 선택 ─────────▶ 모임 상세(05)
모임 상세(05, =이벤트 목록)
 ├─ 선생님 초대하기(초대 화면) ── 모임 비밀번호 + 참여 링크 + 카카오톡
 ├─ 이벤트 생성(06-M, 모달) ─▶ 빈 이벤트(06-E)
 └─ 이벤트 선택 ─▶ 이벤트 상세(08) 또는 빈 이벤트(06-E)
빈 이벤트(06-E) ─▶ 사진 업로드(06-U) ─[사진 분류하기]→ 이벤트 상세(08)
이벤트 상세(08, =앨범 그리드)
 ├─ 앨범 선택 ─▶ 앨범 상세(09)
 │                 └─ 옮기기 ─▶ 사진 이동 바텀시트(09-1)
 └─ 공개 요약(14) ─[공개하기]→ 공개 상태로 전환   ※ 사진 추가 진입점 없음(업로드는 이벤트당 1회)

## 3. 화면별 명세

> 표기: **node** = Figma 노드 id, **API** = 소비 엔드포인트(상세는 [API 명세서](./api-spec.md)).

### 00. 첫 사용 온보딩 · node `348:4`(1/3) · `349:4`(2/3) · `349:19`(3/3)
> ⚠ **현재 노출하지 않는다**(CHMO-504, 2026-07-28 사용자 결정). 첫 로그인 안내는 **00-T 치즈모아 둘러보기**가 맡고, 이 슬라이드로 보내는 진입점(로그인 후 목적지·설정 '사용 방법 다시 보기')은 모두 내렸다. 화면·라우트(`/onboarding`)와 아래 명세는 되살릴 수 있게 남겨 둔다 — 직접 URL로만 열린다. 노출 판정 플래그는 00-T와 **공유한다**(둘을 따로 세면 슬라이드를 되살릴 때 이미 본 사람에게 다시 뜬다).

- **목적**: 로그인 직후, 서비스가 무엇을 대신 해주는지 한 번 보여주고 다음 행동(모임 만들기 / 초대 코드로 참여)으로 연결.
- **요소**: 슬라이드 3장 — 일러스트 카드(350×300, 흰 배경 r20), 제목(24 Bold, 2줄), 설명(14 muted), 도트 3개. 1·2장은 우상단 `[건너뛰기]` + 하단 `[다음]`, 3장은 하단 `[모임 만들기]` + 텍스트 링크 `초대 코드로 참여하기`.
- **문구(확정)**:
  1. "사진만 올리면 / 아이별로 자동 분류돼요" — 선생님이 일일이 고르지 않아도 돼요
  2. "공개 전에 / 선생님이 확인해요" — 잘못 담긴 사진은 옮기거나 지울 수 있어요
  3. "한 번 초대하면 / 공개할 때마다 바로 봐요" — 학부모는 연결된 자기 아이 사진만 봐요
- **확정(CHMO-480) — 3장 문구는 '초대 1회'로 잡는다**: 초안의 "링크 하나로 학부모에게 전달해요"는 **사진을 올릴 때마다 링크를 보내야 하는 것처럼 읽혀 폐기**했다(2026-07-28 사용자 지적). 실제 모델에서 참여 링크는 **모임 합류 초대용(처음 한 번)**이고, 그 뒤로는 이벤트를 공개하면 합류·연결된 학부모 화면에 바로 뜬다(학부모 전환 모델 — `parent-model-proposal.md`). 일러스트도 '링크 → 사진 전달'이 아니라 '초대 링크(처음 한 번) → 모임에 합류한 학부모'로 그린다.
- **액션**: `[건너뛰기]`·마지막 장 이탈 → 홈(02) / `[모임 만들기]` → 03 / `초대 코드로 참여하기` → 홈(02) + 02-1 모달.
- **확정(CHMO-480) — 역할로 나누지 않는다**: 계정에는 role이 없고 role은 **멤버십(모임별) 속성**이다(joinKey 2종이 role을 정함 — `parent-model-proposal.md` §1). 같은 사용자가 A 모임에선 선생님, B 모임에선 학부모일 수 있고 가입 시점엔 어느 쪽인지 알 수 없다. 따라서 온보딩은 **역할 무관 공통 1종**이고, 마지막 장이 진입점 두 개로 갈라주는 역할만 한다. 역할별 심화 안내(검수 흐름·승인 대기)는 멤버십이 정해진 뒤 그 화면 맥락에서 다룬다.
- **확정(CHMO-480) — 노출 시점**: 계정당 1회. BE `AuthResponse`에 신규 가입 여부 필드가 없고 소셜 exchange도 신규·기존을 구분해 주지 않으므로 **FE 로컬 플래그**로 판정한다(기기·브라우저가 바뀌면 재노출되는 것은 감수). 초대 링크로 진입해 `returnTo`가 있으면 온보딩을 건너뛰고 원 목적지를 우선한다 — 참여 흐름을 슬라이드가 끊지 않게. 설정 화면에 '사용 방법 다시 보기' 진입점을 둔다.
- **확정(CHMO-480) — 비주얼**: 신규 일러스트를 만들지 않고 기존 토큰·형태를 재사용한다(치즈 심볼 라운드 사각형, 사진 플레이스홀더 `photo`, 인물 원형 타일, `primary` 강조 1개). 추가 제작 리소스 없이 구현 가능하고 브랜드 톤도 유지된다.
- **API**: 없음(서버 호출 없는 정적 화면).
- **구현**: CHMO-481.

### 00-T. 치즈모아 둘러보기 · node 없음(신규 — 와이어프레임 없음)
- **목적**: `모임 > 이벤트 > 앨범` 정보구조와 **한 바퀴 흐름**(올리기→분류→검토→공개 / 받아보기→저장)을 **눌러서** 체감시킨다. **첫 로그인 안내를 이 화면이 맡는다**(슬라이드 00은 노출하지 않는다 — 아래 참조).
- **방식(확정 CHMO-504)** — **전체 화면 미니 앱**: 실제 화면 위 코치마크가 아니라 축소된 앱 화면을 직접 그리고, 탭하면 다음 계층으로 전환한다. 실제 데이터·라우팅과 무관해 **모임이 하나도 없는 신규 가입자에게도 보여줄 수 있다**(코치마크는 가리킬 대상 자체가 없다). 대가는 실제 화면 디자인이 바뀌면 목업도 손봐야 한다는 것 — 그래서 무대를 **실물 카드 컴포넌트**(`GroupCard`·`EventCard`·`AlbumCard`·`PhotoGrid`)로 조립해 자동 반영되게 한다. 기각: 실제 화면 코치마크 · 샘플 모임 자동 생성(BE 작업 + 삭제 책임).
- **확정(CHMO-504, 2026-07-28) — 초안(310px 모달)은 "촌스럽다"는 피드백으로 폐기**: 낡아 보인 원인 셋을 걷어냈다. ① **액자 제거** — 모달 안 미니 화면에 가짜 `‹ 홈` 상단 바까지 그리던 것을 없애고, 전체 화면 여백 위에 **실물 카드만** 띄운다(어느 화면인지는 실제 화면의 제목·서브텍스트를 그대로 써서 알린다). ② **핫스팟 제거** — 카드 전체를 감싸던 노란 점멸 링은 가장 낡은 튜토리얼 패턴이라 카드 모서리의 작은 탭 물결 하나로 줄였다. ③ **겹 줄이기** — 제목·설명·`1/3` 카운터·링크·버튼 2개까지 일곱 겹이던 것을 **무대 / 문구 / 액션 1개** 세 겹으로 줄이고, 진행은 상단 **세그먼트 바**가 맡는다(한 화면 한 가지). 단계 전환에 페이드+슬라이드(`step-in`)를 넣는다.
- **확정(CHMO-504) — 역할로 갈라 보여준다**: 온보딩 슬라이드(00)는 역할 무관 공통이었지만 **구조는 역할마다 실제로 다르다** — 선생님은 모임→이벤트→앨범 3단이고, 학부모는 **앨범 단계가 없다**(18·19 — 아이 사진이 한 화면에 펼쳐진다). 선생님 흐름만 보여주면 학부모로 합류한 사람은 자기 화면을 못 본다. 그래서 첫 장에서 갈래를 고르고(선생님 / 학부모), 마지막 장에서 반대편으로 건너갈 수 있게 둔다. 고른 갈래는 **계정에 남기지 않는다** — role은 멤버십(모임별) 속성이라 같은 사람이 모임마다 갈릴 수 있다(00과 같은 전제).
- **요소**: 상단 바(`‹` 이전 · 세그먼트 진행바(**칸 수 = 그 갈래의 단계 수**) · `✕` 나가기) · 무대(화면 제목 20 Bold + 서브 13 muted + 실물 컴포넌트) · 문구(제목 22 Bold + 설명 14 muted) · 액션(중간 장은 "카드를/버튼을 눌러 보세요" 한 줄, 마지막 장은 `[다 봤어요]` + 반대편 보기 링크). `[다음]` 버튼은 두지 않는다 — 진행은 무대의 탭이 맡는다.
- **첫 화면(갈래 선택)**: 체다 심볼 + "치즈모아가 어떻게 생겼는지 / 먼저 둘러볼까요?" + 카드 2장(사진을 올려요·선생님 / 아이 사진을 받아요·학부모) + "둘 다 볼 수 있어요 · 고른 쪽은 저장되지 않아요".
- **확정(CHMO-504 2차, 2026-07-29) — 끝까지 보여준다**: 초안은 3단(모임→이벤트→앨범)에서 끊고 검수·공개는 "온보딩 슬라이드가 말로 설명하니 제외"였는데, **그 슬라이드를 더는 띄우지 않게 되면서 아무도 설명하지 않게 됐다**. 선생님은 올리기→분류→검토→공개까지 **7단**, 학부모는 모임→이벤트→사진→저장 **4단**으로 각자 끝을 본다(길이가 다른 건 실제로 할 일이 다르기 때문). 슬라이드 3장이 말하던 분류·검토·공개를 투어가 그대로 흡수한다.
- **확정(CHMO-504 2차) — 탭 대상은 그 화면의 진짜 동작을 따른다**: 들어갈 것이 있으면 **카드**를, 실행할 것이 있으면 **버튼**을 누른다 — 06-U `[사진 분류하기]` · 09 `[검토 완료]` · 14 `[공개하기]` · 19 `[전체 저장]`이 실제 화면의 주 동작이다. 어디서나 카드만 누르게 하면 실제 앱과 손버릇이 어긋난다. 안내 문구도 대상에 따라 갈린다.
- **단계 — 선생님(7)**: 1) 모임 카드(홈) "모임은 우리 반이에요" → 2) 이벤트 카드(05) "이벤트는 하루의 행사예요" → 3) 사진 올리기(06-U) "사진은 한 번에 올려요"(이벤트당 한 번) → 4) 앨범 그리드(08) "잠깐 기다리면 아이별로 나뉘어 있어요" → 5) 앨범 상세(09) "잘못 담긴 사진은 옮기거나 지워요" → 6) 공개 요약(14) "다 검토했으면 공개해요"(검토가 남으면 공개 불가) → 7) 공개된 이벤트 카드 "공개하면 학부모 화면에 바로 떠요".
- **단계 — 학부모(4)**: 1) 모임 카드("학부모 · 참여 중") "모임은 아이 반이에요" → 2) 공개 이벤트 카드(18) "공개된 행사만 보여요" → 3) 사진 그리드(19) "우리 아이 사진만 모여 있어요" → 4) "사진 앱에 한 번에 담겨요".
- **액션**: 탭 물결이 붙은 대상 탭 = 다음 단계 · `‹` = 단계 역행(1단계에서 누르면 갈래 선택으로) · `✕`/ESC = 종료. 이벤트 목록의 두 카드 모두 살아 있고, 누른 이벤트 이름이 이후 장 화면 제목에 그대로 쓰인다(죽은 카드를 만들지 않는다).
- **노출(확정 CHMO-504, 2026-07-28)**: ① **첫 로그인 1회 자동** — 로그인 목적지는 언제나 홈이고(별도 화면으로 튕기지 않는다) 홈 위에서 열린다. 판정은 00과 같은 로컬 플래그(`lib/onboarding.ts`)를 공유하고, 끝까지 보든 `✕`로 나가든 '봤다'로 기록한다(차단 화면이 아니다). 초대 링크 `returnTo`로 02-1이 열려 있으면 미룬다 — 참여 흐름을 가로막지 않는다. ② 설정 → '치즈모아 둘러보기' ③ 홈(02) **빈 상태**(모임 0개).
- **범위 제외**: 초대·승인(20 초대 관리)·아이 연결 — 선생님 흐름 안에서도 한 번 하고 마는 설정이라 그 화면 맥락에서 다룬다. 사진 이동(09-1)·삭제 같은 세부 조작도 뺀다.
- **API**: 없음(서버 호출 없음 · 라우팅 이동 없음).
- **구현**: CHMO-504 (`src/components/AppTour.tsx`).

### 02. 홈 / 내 모임 · node `211:1357`(목록) · `211:1396`(빈 상태)
- **목적**: 참여 중인 모임 목록.
- **요소**: 헤더 "내 모임 / 참여 중인 모임을 확인하세요", 모임 카드 리스트(모임명, `인원 N명 · 이벤트 M개`), `[＋ 모임 만들기]`, `[모임 참여하기]`.

- **확정(CHMO-111)**: 와이어프레임의 카드 내 `모임 설정 ⚙`는 표시하지 않는다 — 모임 설정(이름 수정)은 모임 상세(05)의 `⚙`로 일원화. 카드 전체가 상세 이동 탭 영역이라 내부 `⚙`는 오탭을 유발하고, 디자인 시안(dc.html §05 GroupCard)도 이 형태.
- **승인 대기 카드(CHMO-445 · node `337:4`) — 역할 무관(CHMO-475)**: 합류가 role 무관 승인제가 되면서 **선생님 신청도 이 카드로 온다**. 뮤트 + `승인 대기중` 배지 + 화살표 숨김이고, 탭하면 이동 대신 토스트("선생님 승인을 기다리고 있어요")만 — 대기 전용 화면은 없다(§7-2: 모임 API를 추가로 부르지 않는다). 서브텍스트는 학부모면 신청 원문(`신청: 김민준`), 원문이 없으면 자격만 밝힌다(`선생님으로 참여 신청` / `학부모로 참여 신청`). **대기 카드엔 카운트 줄을 그리지 않는다** — 실 BE가 대기 항목에 `memberCount`를 생략하면서 `eventCount`는 0으로 실어 주기 때문에, 폴백을 열어 두면 "이벤트 0개"가 빈 모임처럼 읽힌다.

### 02-1. 모임 참여(모달) · node `211:1520` / `211:1532`

- **요소**: 헤더 `‹ 이벤트명`, "사진 업로드", `선택됨 N장`, 썸네일 그리드(선택 체크 ✓), 토글 **눈감은 사진 제외(제외 ON)**, 토글 **흔들린 사진 제외(제외 ON)**, 안내 "제외한 사진은 분류가 어려워요 사진첩으로 이동해요", `[사진 분류하기]`.
- **액션**: 사진 선택 → `[사진 분류하기]` 한 번으로 **① presign `POST /events/:id/photos/presign` → ② S3 직접 PUT → ③ 등록 `POST /events/:id/photos`**(제외 옵션 함께 전송)까지 진행 → 배지 `분류중` → 완료(이벤트 상세 2초 폴링 — CHMO-244·287) 시 이벤트 상세(08). **등록(③)이 곧 분석 시작**이라 `POST /analyze`는 부르지 않는다.
- **상태**: 선택 0장 시 CTA 비활성, 업로드 진행률(S3 직접 PUT). 분류 진행률은 이벤트 상세가 `GET /events/:id`의 `progress`를 2초 폴링해 표시하고(CHMO-287 — null이면 인디터미넌트 폴백), 완료 시 08로 자동 전환.
- **확정(CHMO-486, 2026-07-28 정책 변경)**: **업로드·분류는 이벤트당 1회.** 사진이 있는 이벤트(`photoCount > 0`)는 06-U 진입이 차단된다(딥링크 포함) — 분석중 차단과는 다음 할 일이 달라 안내 문구를 가른다. 선택 상한은 **100장**(`MAX_UPLOAD_PICK`, CHMO-397·497 — BE 계약 상한 500장과 별개로 웹이 스스로 거는 값)이고, 상한을 넘긴 잔여분은 **올라가지 않는다는 사실을 그대로 고지**한다("다음에 이어 올리세요"는 1회 정책에선 거짓 안내).
- **확인 필요(플래그)**: 업로드 카피는 "제외→분류가 어려워요"라고 하지만, 08 화면은 `눈감은 사진`/`흔들린 사진` 앨범이 별도로 존재. → 기능 명세에서 "품질 제외 사진은 각 품질 앨범으로 라우팅"으로 정의(아래 08 참고).
- **API**: `POST /events/:id/photos/presign`(→ S3 직접 PUT), `POST /events/:id/photos`(등록=분석 시작), `GET /events/:id`(진행률 폴링)

### 08. 이벤트 상세 = 앨범 그리드 · node `211:1619`
- **목적**: AI 분류 결과 확인·검수 허브.
- **요소**: 헤더 `‹ 이벤트 목록`, "이벤트 상세", 이벤트명("6.15 운동회 오전"), `✎ 수정`, **앨범 카드 그리드(2단)**:
  - ① **앨범 그리드**: 인물 앨범(이름 + `N장` + `검토완료/미검토` 배지)과 `분류가 어려워요`(`uncertain`)를 **동일한 카드 모양(커버 썸네일 포함)으로 같은 그리드**에 배치. 테두리 색 규칙 적용. (분류가 어려워요는 선생님이 아이 앨범으로 재분류할 대상)
  - ② **품질 제외**: `눈감은 사진`, `흔들린 사진`(각 N장) — 하단 별도 섹션
  - 범례: "테두리: 회색 점선=미검토 · 갈색=검토완료" (미검토 먼저 — 처음엔 전부 미검토라 순서가 자연스럽다, CHMO-348)
  - 하단: `[공개 전 요약보기]` (**`[+ 사진 추가]`는 없다** — 업로드·분류가 이벤트당 1회라 진입점을 두지 않는다, CHMO-486. "발행 대기 N장" 안내도 없다 — 재공개 경로 소멸, CHMO-488)
- **액션**: 앨범 탭→09 · 이름 수정→`PATCH /events/:id` · 공개 전 요약보기→14.
- **앨범 종류(확정)**: `person`(아이별), `common`(공통), `uncertain`(분류가 어려워요), `eyes_closed`(눈감은 사진), `blurry`(흔들린 사진). 품질 제외(On) 사진은 `eyes_closed`/`blurry`로, AI가 인물 판단 못 한 사진은 `uncertain`으로 라우팅.
- **인물 앨범 ↔ 모임 단위 인물**: 인물 앨범은 `personId`(모임 단위 인물, 대표 벡터 기반)에 연결된다. **인물 앨범 이름을 바꾸면 그 이름은 모임 단위로 저장돼, 같은 모임의 모든 이벤트에 있는 같은 아이 앨범 이름이 함께 바뀐다**(rename → `PATCH /albums/:id` `name`). 사진은 앨범과 **다대다**(한 사진이 여러 인물 앨범에 속할 수 있음).
- **확정(CHMO-114)**: ① 앨범 카드 커버는 `Album.coverThumbnailUrl`(파생 필드 — `coverPhotoId`만으론 URL 조립 불가)로 노출. ② 레이아웃 = **3열 그리드**(인물·공통·분류어려움) + **품질 제외 별도 섹션**(눈감음·흔들림) + 하단 범례. 앨범/사진이 프레임(844)을 넘을 수 있어 그리드는 스크롤, 하단 액션([공개 전 요약보기])은 고정. ③ 인물 앨범 이름수정(모임 전파)은 **09 앨범 상세 헤더 ✎**(CHMO-115) + **08 그리드 카드 이름 줄 탭**(CHMO-400, 2026-07-22 피드백으로 "08엔 진입점 없음" 결정을 뒤집음 — 이름 뒤 인라인 ✎ 힌트, 텍스트 흐름 안이라 이름 전폭 2줄(CHMO-354) 유지. 커버 오버레이 칩 안은 시안 검토에서 기각. 카드 나머지 영역 탭 = 09 진입 그대로, 인물 앨범만 적용, 모달·이름전파 계약은 09와 동일).
- **확정(CHMO-411)**: **표시 정렬은 FE 소유** — 인물(이름 가나다순, '이름 없음'은 인물 그룹 뒤) → 공통 → 분류가 어려워요, 같은 값은 albumId 고정. **검토 상태와 무관**해 검토 완료해도 앨범 위치가 바뀌지 않는다(실 BE 응답은 미검토 우선+albumId(CHMO-336)라 그대로 쓰면 검토 때마다 순서가 튐 — 목도 실 BE 규칙으로 응답). 정렬 유틸은 `src/lib/albumSort.ts` 단일 원천, **14 미리보기·15 뷰어 앨범 목록도 같은 규칙**(09-1 이동 시트 추천은 유사도 순 — BE 소유라 제외).
- **API**: `GET /events/:id`, `GET /events/:id/albums`, `PATCH /events/:id`(이벤트명), `PATCH /albums/:id`(인물 이름)

### 09. 앨범 상세 · node `211:1685`
- **목적**: 앨범 내 사진 검토/보정.
- **요소**: 헤더 `‹ 이벤트 상세`, 앨범명("김민준"), 사진 그리드(일반 모드 사진 탭 = 라이트박스 크게 보기), `선택` 모드 토글, 선택 시 하단 액션 `[삭제]` `[옮기기]`, `[검토 완료]`.
- **액션**: 선택 모드→사진 체크 → 삭제(`DELETE /photos`, **현재 앨범에서만 제거 = 연결 해제**, 다른 앨범엔 유지, 휴지통 없음) / 옮기기(→09-1) · 검토 완료(`PATCH /albums/:id` `{ reviewed: true }` — **앨범 내 전 사진 일괄 검토**, 검토 상태는 사진 단위).
- **상태**: 선택 0장 시 삭제/옮기기 비활성, 삭제 확인 다이얼로그(warn 색, "이 앨범에서 제거" 문구 · 다른 앨범엔 유지됨 안내).
- **확정(CHMO-114)**: `[검토 완료]`는 비선택 모드에서도 하단에 노출(앨범 단위 일괄), 전 사진 검토 완료면 비활성(`검토 완료됨`). **선택모드의 검토 완료는 선택과 무관하게 앨범 전체가 대상**이라 확인 다이얼로그로 안내(뷰어 공개 고지 포함). **삭제 확인 문구는 결과를 분기**한다 — 선택 사진 중 이 앨범이 마지막 연결인 것이 있으면 "완전 삭제(복구 불가)"를 명시. 사진이 프레임을 넘을 수 있어 그리드는 스크롤·하단 액션은 고정, 저장/삭제 진행 중엔 조작 잠금. (검토 완료는 CHMO-114에서 **단방향** — '검토 완료됨'에서 되돌리는 토글은 미도입, 실수로 학부모 공개 사진을 내리는 위험 회피.)
- **확정(CHMO-115)**: ① `[옮기기]`(선택모드) → **09-1 사진 이동 바텀시트** 실 UI(유사도 추천 + 공통, 이동=연결 교체). ② **인물(person) 앨범만** 앨범명 옆 `✎ 이름`으로 이름 변경 → **모임 단위 인물(personId) 이름을 갱신해 전 이벤트에 전파**(특수 앨범은 미노출). 로컬 캐시가 없어 현재 앨범만 refetch하고, 다른 이벤트 앨범은 다음 진입 시 갱신된 이름으로 조회. 이름 수정 모달은 이벤트명 수정과 **공용 `RenameModal`** 로 통합.
- **확정(CHMO-242)**: 검수 사진 크게 보기(2026-07-14 시연 피드백). ① **일반 모드 사진 탭 = 라이트박스**(16 뷰어 라이트박스를 **공용 `PhotoLightbox`로 승격** — 좌우 스와이프·←/→ 키 이동, `n / N` 카운터, 인접 프리로드). 스타일은 **iOS 사진 앱풍 라이트 크롬**: 흰 배경 풀블리드 + 상단 ✕/카운터·하단 아이콘 툴바(반투명 blur 바, SF Symbols풍 라인 아이콘 — 다크 스크림 아님). 선택모드에선 탭 = 선택 유지 — 선택모드 진입 롱프레스는 CHMO-243 몫(제스처 정합 확정). ② **검수 맥락 배지**: 검토 상태(`검토완료`/`미검토`) + 사진 플래그(`눈감음`/`흔들림`). ③ **하단 툴바 액션**: `[저장]`(개별 저장 — 원본 `downloadUrl`, 업로더 다운로드 용도 포함) · `[옮기기]` · `[삭제]`(현재 1장 대상 — 선택모드와 같은 확인 다이얼로그·09-1 시트 공유, 처리 후 다음 사진으로 이어짐. 삭제는 iOS 휴지통처럼 맨 오른쪽·warn 색). ④ 사진 단위 **'검토' 액션은 미도입** — BE에 사진 단위 검토 API가 없다(앨범 일괄 `PATCH /albums/:id`뿐, api-spec 명시). 앨범 zip 일괄 다운로드도 제작자용 엔드포인트가 없어 제외.
- **확정(CHMO-488, 2026-07-28 정책 변경)**: ① `[검토 완료]`에 **확인 다이얼로그 복원**(CHMO-413에서 뺐던 것) — 검토 **해제가 폐지**돼 되돌리려면 사진을 지우는 수밖에 없다. CHMO-413의 제거 근거("되돌릴 수 있는 표시라 마찰 불필요")가 정책상 사라졌다. 문구는 대상 장수 + 비가역 + 대안("빼야 할 사진은 먼저 삭제하거나 옮기세요"). ② **공개된(`published`) 이벤트에서의 이동은 확인 다이얼로그를 거친다**(09-1) — 옮긴 사진이 `reviewed`·`published`를 유지해 학부모 화면에 즉시 반영되므로 오탭 한 번이 곧 잘못된 노출이다. 미공개 이벤트는 종전대로 즉시 이동(아직 아무도 못 보니 마찰 불필요). 이벤트 상태는 앨범 응답에 없어 09가 `GET /events/:id`를 따로 읽고, **조회 실패 시엔 경고 없이 종전 동작**(겪지 않을 일을 겪은 척하지 않는다).
- **API**: `GET /albums/:id`, `PATCH /albums/:id`, `DELETE /photos`, `GET /events/:id`(이동 확인 판정용)

### 09-1. 사진 이동(바텀시트) · node `211:1866`
- **목적**: 선택 사진의 분류 보정 — **현재 앨범에서 빼고 대상 앨범으로 이동**(다대다에서 연결 교체, 복사 아님).
- **요소**: "다른 사진첩으로 옮기기 / 유사도가 높은 순으로 추천해요", 추천 앨범 리스트(이름 + **유사도 %**, 예 서연 92% / 민준 78% / 하린 65% / 도윤 51%), `공통 사진첩` 옵션.
- **액션**: 대상 선택 → `POST /photos/move`(`sourceAlbumId`+`targetAlbumId`) → 09로 복귀(반영).
- **확정(CHMO-115)**: 09(앨범 상세) 위 **바텀시트**로 구현(별도 라우트 없음 — 초대/공유 시트와 동일 패턴). 추천은 원형 아바타 가로 스크롤(person = 유사도 %, 공통 = `사진첩` 라벨·`similarity: null`). 열릴 때만 `move-suggestions` 조회(선택 사진 `?photoIds=`), 이동 성공 시 시트 닫고 선택 해제 + 상세 refetch. 이동 중 시트 조작 잠금.
- **확정(CHMO-488)**: 공개된 이벤트에서만 대상 탭 → **확인 다이얼로그**("공개된 이벤트예요. 사진 N장을 옮기면 학부모 화면에 바로 반영돼요") → 이동(`confirmImmediateExposure` prop, 09가 이벤트 상태로 판정). **"새 앨범" 타일은 예외** — 이름 입력 + `[만들기]`가 그 자체로 의도 확인이라 다시 묻지 않는다.
- **API**: `GET /albums/:id/move-suggestions`, `POST /photos/move`

### 14. 공개 요약 · node `211:1723`

- **액션**: 미리보기(학부모 뷰 프리뷰) · `[공개하기]`→`POST /events/:id/publish` → 이벤트 상태 `공개됨`(→ 모임 학부모 공유 목록에 노출; 공유 링크/비밀번호는 모임 단위).
- **상태**: 미검토 사진 존재 시 **[공개하기] 비활성 + 남은 앨범 안내**(전량 검토 완료가 하드 게이트 — 정책은 기능 명세 참조).
- **확정(CHMO-116)**: ① 미리보기 = **인라인 3열 썸네일 그리드**(뷰어 노출 규칙 적용 사진 최대 6장, 탭 동작 없는 순수 프리뷰) — 별도 프리뷰 화면 없음. 썸네일 URL은 `review-summary.previewThumbnailUrls`(파생값, `coverThumbnailUrl` 선례). 검토된 노출 사진이 없으면 빈 안내. ② `[공개하기]`는 항상 확인 다이얼로그(학부모 공개는 되돌리기 어려운 외부 노출) — 남는 경고는 **보일 사진 0장**뿐(공개해도 학부모에겐 빈 이벤트 — 거짓 안내 방지). ③ 공개 성공 시 **05 모임 상세로 복귀**(공개 완료 배지·학부모 공유 진입 노출). ④ 버튼은 **공개 가능 상태(`review`/`ready`)에서만 활성** — `published` 재진입은 `공개 완료됨` 비활성, empty/analyzing 딥링크도 비활성(서버 400 방어). ⑤ 공개 실패(이미 공개 등) 시 event·summary **재조회**로 stale 화면 방지(동시 작업 = 정상 시나리오). **05 배지·뷰어 목록 노출은 기존 코드/목이 처리**(별도 작업 없음).
- **확정(CHMO-488, 2026-07-28 정책 변경)**: 미검토가 남으면 `[공개하기]`를 **잠그고**(force 강행·409 자동 재시도 폐기) 통계 아래에 **막고 있는 앨범을 이름·남은 장수로 안내**한다("검토를 모두 마쳐야 공개할 수 있어요 — N개 앨범이 남았어요" + "김민준 3장 · 이서연 5장"). 판정 범위는 **인물·공통뿐**(특수 앨범은 검토 UI가 없어 포함하면 영영 공개 불가 — CHMO-357, 서버 409 범위와 동일). 별도 CTA는 두지 않는다 — 뒤로가기(08 이벤트 상세)가 곧 검토 동선이다. `published` 재진입의 '발행 대기 N장' 안내(08·14)는 **삭제**(재공개 경로 소멸). **미리보기도 발행 대상만 담는다** — 종전엔 '검토 완료 사진이 1장이라도 있는' 인물·공통 앨범을 담았는데(CHMO-346), 발행은 **전 사진 검토된 앨범만** 내보내므로 검수하다 만 앨범이 "학부모가 볼 화면"에 섞여 보였다(공개해도 안 나가는 앨범). 이제 미리보기 = `reviewedAlbumCount`가 세는 집합 = 발행분으로 정확히 일치하고, 카드 테두리가 한 종류뿐이라 **검토 범례(점선/갈색)는 제거**한다(검수 중 남은 앨범은 위 게이트 안내가 이름으로 짚는다). ④ **요약 통계 3열을 공개 기준으로 통일**: 종전엔 `사진`(BE totalPhotos)·`앨범`(BE totalAlbums)이 **이벤트 전체**(특수 앨범 포함)인데 `검토한 앨범 n/m`의 분모만 인물·공통이라 나란히 두면 수가 안 맞았다(예: `사진 28 · 앨범 8 · 1/5`). → `전체 사진 N`(총량임을 라벨로 드러냄) · **`공개할 앨범 N`**(=`previewAlbums.length`, published면 '공개한 앨범') · `검토 n/m`. ⚠ **`공개할 사진` 장수는 FE가 못 센다** — 사진↔앨범이 다대다라 앨범별 `photoCount` 합은 겹친 사진을 중복 집계한다. BE에 중복 제거된 `publishablePhotoCount`를 요청해 두고(CHMO-505), 받으면 첫 칸을 '공개할 사진'으로 전환한다. `albumCount`(BE totalAlbums) 매핑은 소비처가 없어져 제거.
- **확정(CHMO-398)**: 화면명 '공개 전 검수' → **'공개 요약'**, 08 진입 CTA → '요약 보기' — 사진 단위 작업 '검토'와 층위가 겹치던 '검수'를 사용자 노출 문구에서 제거하고, CTA가 "되돌릴 수 있는 이동"으로 읽히게 한다(되돌릴 수 없는 건 14 안의 `[공개하기]`뿐).
- **확정(2026-07-29)**: 08 진입 CTA → **'공개 전 요약보기'** — '요약 보기'만으론 무엇의 요약인지, 왜 지금 보는지가 없어 다음 단계(공개)와 이어지지 않았다. '공개 전'을 붙여 이 화면이 공개 동선의 마지막 정거장임을 CTA에서 드러낸다(화면명 '공개 요약'은 그대로).
- **API**: `GET /events/:id/review-summary`, `POST /events/:id/publish`

### 15-L. 공개 이벤트 목록 (뷰어, 무로그인) · node (신규, 와이어프레임 없음)
- **목적**: 학부모가 모임의 **공개된 이벤트 중 하나**를 선택.
- **진입**: 모임 공유 링크(`/share/:token`) → 학부모 전용 비밀번호 입력(잠금 해제) 후 도달.
- **요소**: 헤더, 모임명, **공개(published) 이벤트 카드 리스트**(이벤트명·날짜·`사진 N장`·커버 썸네일). 공개된 이벤트 없으면 빈 상태.
- **액션**: 이벤트 탭 → 공개 이벤트 앨범(15).
- **확정(CHMO-117)**: ① 잠금 해제 화면 = BrandHero + 학부모 전용 비밀번호(숫자 4자) 입력 — 이미 해제된 링크(viewerToken 보유)는 자동 통과, 뷰어 API 401 시 apiFetch가 토큰을 지워 이 화면으로 복귀. ② 15-L = 홈형 헤더(로고) + 모임명 + 세로 카드 리스트(76px 커버 썸네일 + 이벤트명 + `날짜 · 사진 N장`). 커버 URL은 `ViewerEvent.coverThumbnailUrl`(파생 — `coverThumbnailUrl` 선례, 검토 완료 사진 기준).
- **API**: `POST /share/:token/unlock`, `GET /share/:token`

### 15. 공개 이벤트 앨범 (뷰어, 무로그인) · node `211:1754` / `211:1789`
- **목적**: 학부모가 선택한 공개 이벤트의 앨범을 조회.
- **진입**: 15-L(공개 이벤트 목록)에서 이벤트 선택 후 도달.
- **요소**: 헤더 `‹`, "공개 이벤트 앨범", `공개됨` 배지, 이벤트명, **인물 앨범 + 공통 앨범**(각 `N장`). (특수 앨범 `분류가 어려워요/눈감은/흔들린`은 **뷰어에 노출하지 않음**.)

### 16. 인물 앨범 상세 (뷰어, 무로그인) · node `211:1822` / `211:1844`
- **목적**: 특정 인물 앨범 조회 + 받기.
- **요소**: 헤더 `‹ 공개 이벤트 앨범`, 인물명, 사진 그리드, `[⤓ 다운로드]`, `[↗ 공유]`.
- **액션**: 다운로드(앨범 일괄/개별) · 공유(링크 재공유).
- **확정(CHMO-117)**: ① 개별 다운로드 = 사진 탭 → 라이트박스(크게 보기 + `[⤓ 이 사진 저장]` — 와이어프레임 없는 표면, 최소 구현). ② `[⤓ 다운로드]` = 일괄 zip(`/download`의 `downloadUrl` 트리거). ③ `[↗ 공유]` = Web Share API, 미지원·실패 시 링크 복사(사용자 취소만 무시) — 공유 대상은 잠금 해제 입구 URL(`/share/:token`, 뷰어 딥링크 아님). ### 설정 / 프로필 편집 · node `240:53`
- **목적**: 닉네임·PIN 변경.
- **요소**: 헤더 `‹ 설정`, "프로필 편집", 닉네임, "PIN 번호 변경 (숫자4자)", `[저장]`.
- **액션**: 저장 → `PATCH /me`.
- **확정(CHMO-118)**: ① 헤더는 기존 서브형 관례(`‹ 홈` + 타이틀 "설정")로 적용, "프로필 편집"은 본문 제목 — 와이어프레임의 `‹ 설정`은 별도 설정 목록 화면 전제인데 MVP IA에는 그 화면이 없음. ② 닉네임은 `GET /me`로 프리필. PIN은 응답에 없어 빈 칸 시작 — **입력했을 때만** `PATCH /me`에 포함(빈 값 = 닉네임만 변경). `[저장]`은 **실제 변경이 있을 때만 활성**(닉네임 수정 또는 새 PIN 4자리 완성 — 무변경·PIN 미완성이면 비활성). 저장 중엔 입력 필드도 잠근다(늦은 응답이 입력을 덮지 않게). ③ **로그아웃 버튼 포함**(하단 `[저장]` 위 secondary, MVP 스코프 확정 사항) — 앱 유일의 로그아웃 표면이라 프로필 로딩/실패 중에도 상시 노출. 토큰 삭제 후 01 로그인 진입으로 복귀.
- **API**: `GET /me`, `PATCH /me`

## 5. 구현 시 확정 필요 항목(요약)
1. 홈의 `관리자` 배지/`📌` 고정 — 권한 제거에 따라 미표시(추후 재도입 여지).
2. `⧉ 학부모님에게 공유` — **모임 단위 공유로 확정**(05에 위치, `GET /groups/:id/share`). 학부모 전용 비밀번호(모임 비밀번호와 별개, 생성 시 자동), 비번 후 공개 이벤트 목록(15-L)에서 선택. (더 이상 미정 아님 · 신규 화면 15-L은 와이어프레임 없음 → 시안 필요)
3. 품질 제외 사진 라우팅 — `눈감은 사진`/`흔들린 사진` 앨범으로(08 기준), 업로드 카피와 정합 맞추기.
4. `공통(common)` 앨범 정의 — 앨범↔사진 다대다 확정으로 "다수 인물"은 각 아이 앨범에 모두 들어가므로, `공통`은 **특정 아이로 분류되지 않은 사진(단체/배경 등)**으로 좁혀 정의(구현 시 확정).
5. 도메인 `classpic.app` → 치즈모아 도메인(placeholder).
6. 온보딩(00) 완료 상태 저장 위치 — FE 로컬 플래그(기기별) vs `/me` 필드(계정별). MVP는 로컬로 가고, 서버 저장은 BE 협의 후 별도 스토리(CHMO-481 제외 항목).

> **참고**: 다대다(사진=여러 앨범), 삭제=현재 앨범에서만 제거(연결 해제), 옮기기=연결 교체, 인물 이름=모임 단위 공유(rename 그룹 전파)는 ERD 반영으로 **확정**됨(더 이상 미정 아님).
