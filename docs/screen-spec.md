## 0. 확정 모델 요약 (모든 화면의 전제)

- **타깃**: 기관(B2B/유치원) 우선.
- **정보구조**: `모임(Group) > 이벤트(Event) > 앨범(Album)`.
- **인증(제작자)**: 소셜 로그인 4종(카카오·구글·네이버·애플 — CHMO-359, 4종 실 BE 배포 완료). 닉네임+4자리 PIN은 **화면에서 내렸다**(CHMO-557 — 01-1·01-2 삭제, DEV 전용 `/dev/login`만 잔존. BE `/auth/login`·`/auth/signup` 엔드포인트가 제거되면 그마저 걷는다).
- **권한**: 등급 없음. 로그인한 모임 멤버는 누구나 업로드·검수·공개 가능.
- **모임 진입점 2개(분리)**
  - **선생님 초대** = 로그인 제작자를 모임에 합류시키는 입구. **모임 단위**(모임 비밀번호 + 참여 링크).
  - **학부모 공개** = 무로그인 뷰어(조회·다운로드만). **모임 단위** 공유 링크 + **학부모 전용 비밀번호**(모임 비밀번호와 별개, 생성 시 자동). 비번 입력 후 **공개된 이벤트 목록**에서 선택.
- **공개(publish) 단위**: **이벤트별** (검수 → 공개 요약 → 공개하기). **학부모 접근(공유) 단위**: **모임별**(공개된 이벤트만 목록 노출).
- **BE/AI 미구현**: FE는 [API 명세서](./api-spec.md) 계약에 목 데이터로 개발.

## 1. 디자인 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `--color-primary` | `#FFC93C` | 주요 버튼/강조(치즈 옐로우) |
| `--color-accent` | `#8C5A2B` | 검토완료 테두리/보조 강조(갈색) |
| `--color-warn` | `#E4572E` | 되돌릴 수 없는 동작(삭제 등) + 실패 알림 |
| `--color-bg` | `#FFFDF5` | 페이지 배경 |
| `--color-surface` | `#F3F0E9` | 카드/입력 표면 |
| `--color-text` | `#3A3128` | 본문 텍스트 |
| `--color-muted` | `#9E978C` | 보조 텍스트/플레이스홀더 |
| `--color-border` | `#E6E0D4` | 구분선/기본 테두리 |

- **`warn`(빨강) 사용 규칙(2026-07-29 확정)**: ① 되돌릴 수 없는 동작 — 삭제(모임·이벤트·앨범·사진), 신청 거절, 아이 연결 해제 ② 실제 실패 알림(`role="alert"` 인라인 에러·`ErrorState`·입력 검증). **그 외 안내성 문구에는 쓰지 않는다** — 아직 할 일이 남았다는 안내(14 공개 게이트, 06-U 미선택 사진 고지)는 `heading`, 상태 라벨(09 라이트박스 눈감음·흔들림)은 중립 칩. 빨강을 안내에 쓰면 "내가 뭘 잘못했나"로 읽히고, 정작 삭제 버튼이 같은 색이라 위험 신호가 묽어진다.
- **서체는 Jua 한 벌(CHMO-513, 2026-07-30 확정)**: 로고 워드마크와 본문이 같은 얼굴을 쓴다(종전 Jua+Gothic A1 2종 폐지, `font-display` 토큰도 제거). **Jua는 굵기가 400 하나뿐이라 굵기로 위계를 만들 수 없다** — `index.css`가 합성 볼드를 차단하므로(`font-synthesis: none`, 안 막으면 브라우저가 가짜 굵기를 만들어 획이 뭉갠다) `font-bold`는 시각 효과가 없고 **위계는 크기·색이 만든다**. 굵기가 유일한 구분이었던 두 곳은 다시 벌려 놨다: ① **섹션 라벨**(홈 '모임'·05 '이벤트'·08 '공개해도 학부모에게 안 보여요'·14 '미리보기'·20 명단 머리글·시트 소제목) = `12px + 자간 0.06em + muted`, 바로 위 13px 본문과 크기로 갈린다 ② **약관 전문 조문 제목** = 장(`17px heading`) > 조(`15px heading`) > 본문(`14px text`), 색이 목차를 만든다.
- **앨범 카드 테두리 규칙**: 갈색(`accent`) 실선 = 검토완료 · 회색(`border`) 점선 = 미검토. (기준: 앨범 내 미검토 **사진** 유무 — 검토는 사진 단위, `unreviewedPhotoCount`로 판정)
- 상단 상태바(`9:41`)는 디바이스 영역으로 구현 대상 아님.

## 3. 화면별 명세

> 표기: **node** = Figma 노드 id, **API** = 소비 엔드포인트(상세는 [API 명세서](./api-spec.md)).

### 00. 첫 사용 온보딩 · node `348:4`(1/3) · `349:4`(2/3) · `349:19`(3/3)
> ⚠ **현재 노출하지 않는다**(CHMO-504, 2026-07-28 사용자 결정). 첫 안내는 실제 화면의 **코치 힌트**(CHMO-565·578 — 00-T 카드 참조)가 맡고, 이 슬라이드로 보내는 진입점(로그인 후 목적지·설정 '사용 방법 다시 보기')은 모두 내렸다. 화면·라우트(`/onboarding`)와 아래 명세는 되살릴 수 있게 남겨 둔다 — 직접 URL로만 열린다. 노출 판정 플래그(`onboarded`, `lib/onboarding.ts`)도 기록을 유지한다 — 되살릴 때 "이미 첫 안내를 본 사람"을 가르는 판정 원천이다.

- **목적**: 로그인 직후, 서비스가 무엇을 대신 해주는지 한 번 보여주고 다음 행동(모임 만들기)으로 연결.
- **요소**: 슬라이드 3장 — 일러스트 카드(350×300, 흰 배경 r20), 제목(24, 2줄), 설명(14 muted), 도트 3개. 1·2장은 우상단 `[건너뛰기]` + 하단 `[다음]`, 3장은 하단 `[모임 만들기]` + 안내 한 줄 "초대받은 모임은 받은 링크로 들어와요."
- **문구(확정)**:
  1. "사진만 올리면 / 아이별로 자동 분류돼요" — 선생님이 일일이 고르지 않아도 돼요
  2. "공개 전에 / 선생님이 확인해요" — 잘못 담긴 사진은 옮기거나 지울 수 있어요
  3. "한 번 초대하면 / 공개할 때마다 바로 봐요" — 학부모는 연결된 자기 아이 사진만 봐요
- **확정(CHMO-480) — 3장 문구는 '초대 1회'로 잡는다**: 초안의 "링크 하나로 학부모에게 전달해요"는 **사진을 올릴 때마다 링크를 보내야 하는 것처럼 읽혀 폐기**했다(2026-07-28 사용자 지적). 실제 모델에서 참여 링크는 **모임 합류 초대용(처음 한 번)**이고, 그 뒤로는 이벤트를 공개하면 합류·연결된 학부모 화면에 바로 뜬다(학부모 전환 모델 — `parent-model-proposal.md`). 일러스트도 '링크 → 사진 전달'이 아니라 '초대 링크(처음 한 번) → 모임에 합류한 학부모'로 그린다.
- **액션**: `[건너뛰기]`·마지막 장 이탈 → 홈(02) / `[모임 만들기]` → 03.
- **변경(CHMO-513) — 참여 링크 CTA 삭제**: 3장의 텍스트 링크 `초대 코드로 참여하기`는 홈으로 `openJoin` 신호를 보내 02-1 모달을 열었는데, 홈에서 참여 진입점을 없애면서(02) 받을 곳이 사라졌다. 자리에는 사실만 남긴다("초대받은 모임은 받은 링크로 들어와요.") — 초대받은 사람은 이 화면을 지나갈 필요 없이 링크로 곧장 02-1·02-2에 들어간다.
- **확정(CHMO-480) — 역할로 나누지 않는다**: 계정에는 role이 없고 role은 **멤버십(모임별) 속성**이다(joinKey 2종이 role을 정함 — `parent-model-proposal.md` §1). 같은 사용자가 A 모임에선 선생님, B 모임에선 학부모일 수 있고 가입 시점엔 어느 쪽인지 알 수 없다. 따라서 온보딩은 **역할 무관 공통 1종**이고, 마지막 장이 진입점 두 개로 갈라주는 역할만 한다. 역할별 심화 안내(검수 흐름·승인 대기)는 멤버십이 정해진 뒤 그 화면 맥락에서 다룬다.
- **확정(CHMO-480) — 노출 시점**: 계정당 1회. BE `AuthResponse`에 신규 가입 여부 필드가 없고 소셜 exchange도 신규·기존을 구분해 주지 않으므로 **FE 로컬 플래그**로 판정한다(기기·브라우저가 바뀌면 재노출되는 것은 감수). 초대 링크로 진입해 `returnTo`가 있으면 온보딩을 건너뛰고 원 목적지를 우선한다 — 참여 흐름을 슬라이드가 끊지 않게. 설정 화면에 '사용 방법 다시 보기' 진입점을 둔다.
- **확정(CHMO-480) — 비주얼**: 신규 일러스트를 만들지 않고 기존 토큰·형태를 재사용한다(치즈 심볼 라운드 사각형, 사진 플레이스홀더 `photo`, 인물 원형 타일, `primary` 강조 1개). 추가 제작 리소스 없이 구현 가능하고 브랜드 톤도 유지된다.
- **API**: 없음(서버 호출 없는 정적 화면).
- **구현**: CHMO-481.

### 00-T. 치즈모아 둘러보기 — **삭제(CHMO-578)** → 첫 안내는 코치 힌트
- 전체 화면 미니 앱 투어(CHMO-504 구현 — 실물 카드 컴포넌트로 조립한 선생님 7단·학부모 4단)는 **자동 노출 폐지(CHMO-565)**를 거쳐 **설정 pull 진입점까지 걷어냈다**(2026-08-03 사용자 결정 — 효용이 낮다). 근거는 CHMO-565 리서치 그대로: NN/g 정량 실험(선행 튜토리얼은 과업 성공률을 못 올리고 체감 난이도만 악화), 자동 노출 완주율 39% vs 스스로 연 투어 67%, 직접 경쟁 서비스(키즈노트·하이클래스)도 앱 내 투어 없음. 컴포넌트(`AppTour.tsx`)·전용 keyframe(`tap-ripple`)·설정 진입점을 삭제했다. 온보딩 슬라이드(00)와 달리 **화면을 남겨 두지 않는다** — 되살릴 일이 생기면 그때의 화면 구조로 다시 설계하는 편이 싸다(무대가 실물 컴포넌트라 화면이 바뀔 때마다 따라 수선해야 했다).
- **첫 안내는 코치 힌트(`ui/CoachHint`, CHMO-565·578)가 전담한다**: 실제 화면의 낯선 지점에 **계정당 힌트 id별 1회** 붙는 말풍선. 딤·오버레이·pointer-events 없음(아래 카드·버튼 탭을 막지 않는다) · 아무 곳이나 탭(click — 터치 스크롤로는 안 닫힘)하면 소멸 · '봤다' 기록은 닫을 때가 아니라 **뜰 때**(새로고침 이탈로 1회 보장이 깨지지 않게). 기록은 `lib/onboarding.ts`가 계정별로 소유.
- **배치 4곳(화면당 동시 1개)**:
  1. 08 첫 앨범 카드(`album-grid`) — "사진이 아이별로 나뉘었어요 / 앨범을 눌러 확인해 보세요". 앨범 0개면 비노출.
  2. 09 [검토 완료] 버튼(`album-review`) — "다 봤으면 검토 완료를 눌러 주세요 / 모든 앨범을 검토해야 공개할 수 있어요". 전량 검토된 앨범엔 비노출(죽은 버튼을 가리키는 거짓 안내 방지).

### 01-A. 가입 동의 · `/consent` (CHMO-479 — 정본 `docs/legal/app-copy.md` §1~§4)
- **목적**: 로그인 후 필수 동의 수집. **신규 가입은 이제 이 화면에 오지 않는다**(CHMO-602 — 소셜 가입은 01-C의 가입 분기가, PIN 가입은 signup 동봉(CHMO-600)이 동의를 가입과 한 트랜잭션으로 기록) — 남는 대상은 동의 기록이 없는 기존 계정과 문구 개정 재동의다. 폼은 01-C 가입 분기와 공용(`SignupConsentForm`).
- **진입**: 로그인 성공 시점(01-C 콜백 **기존 유저 경로**·DEV 로그인)이 `GET /agreements`를 읽어 `lib/consentGate.evaluateConsentGate`로 판정 — 필수(USER 스코프) 미동의가 있으면 여기로, 아니면 종전 목적지(홈/returnTo) 직행. **조회 실패는 통과**(게이트는 FE 몫 — 서버 전역 강제는 CHMO-519 후속). GROUP 스코프(보호자 확인)는 `agreed`가 항상 false라 판정에서 제외(정본 §1 함정).
- **요소**: 제목 "서비스 이용 동의" · `[전체 동의]`(카드형 — 일반 3종만) · 체크박스: (필수) 만 14세(§4 설명 캡션, 전문 없음) · (필수) 이용약관 `[전문 보기]` · (필수) 개인정보 수집·이용 `[전문 보기]` · **구획선 + "얼굴 인식 기능 동의 (별도)"** 아래 (필수) 얼굴 특징정보 처리 `[전문 보기]` · 하단 안내(§1.2) + `[동의하고 시작하기]`(4종 전부 체크 시에만 활성).
- **설계 제약(정본 §1.1)**: ① 얼굴 특징정보는 **전체 동의에 포함 금지**(법 제23조 민감정보 별도 동의 — 별도 영역 개별 체크) ② **필수 기본 체크 금지**. 마케팅(선택)은 **넣지 않는다**(2026-08-03 결정 — 발송 채널이 없어 전문을 사실대로 쓸 수 없다. 채널 생기면 전문·"선택 항목은 미동의로도 이용 가능" 안내와 함께 추가).
- **[전문 보기]**: 바텀시트(bodyScrollable)로 화면 이탈 없이 — 체크 상태가 라우팅에 날아가지 않게. 렌더러는 `/legal/*`와 같은 `LegalDocBody`. 이용약관=전문 문서 그대로, 개인정보=동의 시점 고지 전문(§2 — 처리방침 요약이 아니라 제15조② 고지), 얼굴=§3 요약 전문(상세판은 `/legal/biometric`).
- **제출**: `POST /agreements` 4종 일괄 `agreed: true`, **버전은 화면에 보여준 FE 문구의 것**(CHMO-517 — 서버 에코 금지). 성공 시 returnTo(없으면 홈) replace 이동.
- **상태**: 서버 버전 ≠ FE 버전이면 폼 대신 **새로고침 안내**(구버전 번들 캐시 — 체크 받아도 제출이 VALID400이라 체크부터 시키지 않는다) · 이미 전부 동의된 계정의 직접 진입은 홈으로 replace · 제출 중 전 컨트롤 잠금.

### 01-C. 소셜 콜백 · `/auth/callback` (CHMO-359 · 가입 유예 CHMO-602)
- **목적**: BE 인가 복귀(`?code=일회용코드` 또는 `?error=OAUTH400|OAUTH401|OAUTH502`)를 받아 토큰 교환 후 원 목적지로 — 기존 유저는 "로그인 처리 중" 한 줄이 전부다(즉시 exchange → 01-A 게이트 판정 → 복귀, 종전 그대로).
- **가입 분기(CHMO-602 — BE 소셜 가입 유예, CHMO-598의 소셜판)**: 미가입 소셜 신원이면 BE가 콜백에서 계정을 만들지 않고 `&signup=true`(가입 대기 코드, TTL 10분)를 실어 보낸다 → **exchange 전에 가입 동의 폼(01-A와 공용 `SignupConsentForm`)을 이 화면이 그리고**, 동의 완료 시 `POST /auth/social/exchange`에 필수 4종(agreed:true — MARKETING 미동봉·버전은 FE 문구, CHMO-600과 같은 결정)을 동봉해 그때 가입된다. **동의 없이 계정이 만들어지는 경로가 구조적으로 없다.** 새로고침해도 code·signup이 URL에 남고 코드는 미소진이라 폼이 다시 선다.
- **가입 성공 후**: 동의를 방금 냈으므로(가입·동의가 한 트랜잭션) 01-A 게이트 조회 없이 바로 원 목적지(returnTo/홈) replace.
- **에러**: 제출 VALID400(필수 미동의·버전 불일치)은 **코드가 소비되지 않아** 폼 유지 + 에러 표시 + 재시도 · OAUTH401(가입 대기 코드 만료·소진)은 "가입 유효 시간이 지났어요" + `[다시 로그인]` · `?error=` 복귀·code 없는 진입은 종전 실패 화면 그대로.
- **목(MSW)**: 서비스워커가 내비게이션을 못 가로채 signup 판정을 URL 생성(socialLoginStartUrl)이 한다 — 원천은 프로바이더 목 계정의 존재(persist 보존소, `lib/mockSocial`). 첫 소셜 로그인 = 가입 분기, 이후 = 로그인이고 계정 삭제(DELETE /me) 후에는 다시 가입 분기. 목 exchange도 신규면 signup과 같은 동의 검증(실패 VALID400은 코드 미소진) 후 계정+동의 행을 함께 만든다.

### 02. 홈 / 내 모임 · node `211:1357`(목록) · `211:1396`(빈 상태)
- **목적**: 참여 중인 모임 목록.
- **요소**: 헤더 "내 모임 / 참여 중인 모임을 확인하세요", 섹션 라벨 `모임`, 모임 카드 리스트(모임명, `멤버 N · 이벤트 M`), `[＋ 모임 만들기]`.
- **액션**: 카드 탭→모임 상세(05, 학부모 멤버십이면 18) / 모임 만들기→03.
- **확정(CHMO-513) — 참여 진입점 없음**: 하단 보조 버튼 `[모임 참여하기]`를 없앴다. **모임 참여는 링크로만** 이뤄진다 — 받은 링크를 누르면 02-1(선생님)·02-2(학부모)로 곧장 들어가므로, 참여 코드를 손으로 넣는 문은 모든 사용자에게 상시 노출될 이유가 없다(코드를 받아 온 사람만 쓰던 문이다). 링크 진입 화면과 02-1 모달 자체는 그대로 산다. ⚠ 딸린 결정: 05 초대 시트가 **참여 코드 텍스트를 계속 보여줄지는 미정** — 받는 쪽에 입력란이 없어져 죽은 정보가 된다(§5).
- **상태**: **빈 상태**(`211:1396`) = 모임 카드 없이 `[＋ 모임 만들기]` 하나. 설명은 **"첫 모임을 만들어 보세요."** — 종전 "첫 모임을 만들거나 / 초대받은 모임에 참여해 보세요"는 앱 안에 그 방법이 없어져 사실과 달라졌다(CHMO-513).
- **확정(CHMO-111)**: 와이어프레임의 카드 내 `모임 설정 ⚙`는 표시하지 않는다 — 모임 설정(이름 수정)은 모임 상세(05)의 `⚙`로 일원화. 카드 전체가 상세 이동 탭 영역이라 내부 `⚙`는 오탭을 유발하고, 디자인 시안(dc.html §05 GroupCard)도 이 형태.
- **승인 대기 카드(CHMO-445 · node `337:4`) — 역할 무관(CHMO-475)**: 합류가 role 무관 승인제가 되면서 **선생님 신청도 이 카드로 온다**. 뮤트 + `승인 대기중` 배지 + 화살표 숨김이고, 탭하면 이동 대신 토스트("선생님 승인을 기다리고 있어요")만 — 대기 전용 화면은 없다(§7-2: 모임 API를 추가로 부르지 않는다). 서브텍스트는 학부모면 신청 원문(`신청: 김민준`), 원문이 없으면 자격만 밝힌다(`선생님으로 참여 신청` / `학부모로 참여 신청`). **대기 카드엔 카운트 줄을 그리지 않는다** — 실 BE가 대기 항목에 `memberCount`를 생략하면서 `eventCount`는 0으로 실어 주기 때문에, 폴백을 열어 두면 "이벤트 0개"가 빈 모임처럼 읽힌다.
- **확인 필요(플래그)**: 와이어프레임의 `관리자` 배지·`📌` 고정 아이콘은 권한 등급 제거 결정에 따라 MVP에서 표시하지 않음(추후 재도입 여지).
- **API**: `GET /groups`

### 02-1. 모임 참여(모달) · node `371:31`(일반) / `211:1520`(신청 꼴)
- **목적**: 초대받은 모임에 참여. **일반(GENERAL) 모임 링크면 참여 꼴, 그 외(비즈니스 관리자 키·마커 없음)는 참여 신청 꼴** — 한 모달이 링크 마커(`lib/joinLink`)로 갈린다(CHMO-607).
- **요소(일반)**: "모임 참여", **모임명 + `멤버 N · 이벤트 N개`**(링크 동봉 스냅샷 — 없는 값은 그 줄만 생략), 비밀번호 입력, `[참여하기]`. 안내 문구 없음(회색 보조 문구 최소화 — 정본 §1-1).
- **요소(신청 꼴)**: "모임 참여 신청 / {모임명} 모임의 비밀번호를 입력하세요. 모임 관리자가 승인하면 이용할 수 있어요.", (링크 진입이 아니면) 참여 코드 입력, 비밀번호 입력, `[참여 신청]`.
- **진입 경로**: **초대 링크(`/join/:joinKey`)뿐이다**(CHMO-513 — 홈의 `모임 참여하기` 진입점 삭제) → 링크가 모임을 식별하고 비밀번호만 입력한다. 코드 입력란은 링크 없이 열렸을 때를 위한 폴백으로 코드에 남아 있으나, 화면상 그 경로는 없다.
- **모임 정보의 원천은 링크다(CHMO-607)**: joinKey는 불투명 값이고 joinKey→모임 정보 조회 API가 실 BE에 없어(SpaceController 실확인), 링크 생성 화면(20)이 유형·모임명·멤버/이벤트 수를 쿼리 마커로 동봉한다(2026-08-06 확정 — **공유 시점 스냅샷**이라 이름 변경·인원 변동은 다음 공유 전까지 반영 안 됨). 마커 계약은 `lib/joinLink` 단일 원천.
- **액션**: 제출 → `POST /groups/join` → 응답 status 분기(CHMO-607): **ACTIVE면 모임 상세(05) 직행**, PENDING이면 홈(02) 승인 대기 카드. ⚠ 일반 모임 즉시 합류는 BE 미구현(현행 role 무관 승인제 — CHMO-599)이라 직행은 BE 확정 전까지 잠들어 있는 갈래다.
- **확정(CHMO-475) — 승인제**: joinKey는 "누가 신청할 수 있나"만 정하고 "누가 들어오나"는 관리자가 승인으로 정한다. 모임 **생성자만 예외**로 즉시 참여 상태다(03).
- **직행 안전장치(CHMO-607 — CHMO-445 '무조건 홈' 완화)**: 직행은 **명시적 ACTIVE에만** 열린다. join 응답은 실 BE가 `GroupSummaryResponse`(role·status가 `myMembership` 중첩)를 재사용하는데, 종전 매퍼는 평면만 읽고 기본값을 active로 둬 과도기에 상세 직행이 권한 오류(SPACE403)로 터졌다(CHMO-448 실측). 매퍼가 중첩을 읽고 형태 미상은 **pending으로 좁혀** 홈으로 보낸다.
- **상태**: 비밀번호 불일치(JOIN403) · 이미 신청·참여한 모임(409) 인라인 에러. viewer(멤버) 코드를 마커 없이 넣으면 서버 400(인물 이름 필요)으로 감지해 02-2로 인계한다(안전망).
- **API**: `POST /groups/join`

BE 변경 없음. **사진이 있는 이벤트만** 커버를 지고 사진 0장은 컴팩트 카드로 남아, 목록만 봐도 "아직 올릴 차례"가 보인다(등록 직후 분류중은 사진 반영이 분석 커밋 시점이라 잠시 컴팩트로 지나간다). 커버 URL이 없으면 치즈 도트 플레이스홀더. ⑤ **사진 스트립(카드당 4~5장)은 후속** — 목록 응답엔 커버 1장뿐이라 BE 미리보기 URL 배열이 필요하다. 전면 커버 자리를 스트립으로 바꾸는 변경이라 지금 넣은 것을 버리지 않는다. ⑥ `이벤트/멤버` 세그먼트 탭은 넣지 않았다(멤버 명단·승인·아이 연결이 20에 있어 IA 재편 결정이 선행) · '권한 관리' 워딩도 쓰지 않는다(권한 등급이 없는 모델이라 없는 개념을 만든다).

### 08. 이벤트 상세 = 앨범 그리드 · node `211:1619`
- **목적**: AI 분류 결과 확인·검수 허브.
- **요소**: 헤더 `‹ 모임` + **중앙 타이틀 = 이벤트명**("6.15 운동회 오전") + `⚙`(이벤트 설정 — 이름 수정·삭제), **앨범 카드 그리드(3열)**:
  - ① **앨범 그리드**: 인물 앨범(이름 + `N장` + `검토완료/미검토` 배지) + `공통`. 테두리 색 규칙 적용.
  - ② **"공개해도 학부모에게 안 보여요"**: `분류가 어려워요`, `눈감은 사진`, `흔들린 사진`(각 N장) — 하단 별도 섹션
  - 범례: "점선=미검토 · 채운 면=검토완료" (미검토 먼저 — 처음엔 전부 미검토라 순서가 자연스럽다, CHMO-348 · 선이 아니라 **면**이 상태를 만들게 바뀌어 범례 문구도 따라갔다, CHMO-531)

- **액션**: 앨범 탭→09 · 이름 수정→`PATCH /events/:id` · 공개 전 요약보기→14.
- **앨범 종류(확정)**: `person`(아이별), `common`(공통), `uncertain`(분류가 어려워요), `eyes_closed`(눈감은 사진), `blurry`(흔들린 사진). 품질 제외(On) 사진은 `eyes_closed`/`blurry`로, AI가 인물 판단 못 한 사진은 `uncertain`으로 라우팅.
- **인물 앨범 ↔ 모임 단위 인물**: 인물 앨범은 `personId`(모임 단위 인물, 대표 벡터 기반)에 연결된다. **인물 앨범 이름을 바꾸면 그 이름은 모임 단위로 저장돼, 같은 모임의 모든 이벤트에 있는 같은 아이 앨범 이름이 함께 바뀐다**(rename → `PATCH /albums/:id` `name`). 사진은 앨범과 **다대다**(한 사진이 여러 인물 앨범에 속할 수 있음).
- **확정(CHMO-522) — 헤더 중앙은 이벤트명, 본문 큰 제목은 없앤다**: 종전엔 헤더가 `이벤트 상세`(어느 이벤트인지 말하지 않는 화면 종류명)를 달고 본문 첫 줄이 이벤트명을 다시 말해 같은 자리를 두 번 썼다(CHMO-515에서 "별도 판단"으로 남겨 둔 중복). 05가 같은 이유로 헤더 타이틀을 **비운** 것과 결론이 갈리는 이유는 하나다 — **05는 본문 제목이 남았고 08은 그 제목을 없애 스크롤해도 이름이 보이는 쪽을 골랐다**(앨범 그리드는 스크롤이 길어 본문 제목이 곧 사라진다). 긴 이름은 헤더 중앙에서 잘리므로 뒤로가기 라벨을 `‹ 이벤트 목록` → **`‹ 모임`**으로 줄여 폭을 넓혔고(09의 뒤로가기도 `‹ 이벤트 상세` → **이벤트명**), 없앤 한 줄만큼 앨범이 한 줄 더 보인다. 06-E·분류중 분기는 상태 배지가 본문 제목 옆에 붙어 있어 종전 배치를 유지한다.
- **확정(CHMO-522) — 인물 앨범 카드 이름 줄 탭 = 앨범 설정 시트**: 이름 수정만 하던 모달을 **`AlbumSettingsSheet`(바텀시트)**로 넓혀 **아이 이름 수정 + 학부모 연결**을 한 자리에서 처리한다(09 헤더 `[✎ 앨범 설정]`과 같은 시트 — 상세는 09 카드 참조). 08 진입에는 **앨범 삭제를 두지 않는다**: 카드 이름 줄 탭에서 앨범이 사라지는 동작까지 열지 않는다(삭제는 09에서만).
- **확정(CHMO-523, 2026-07-30) — 08 구획 기준은 "공개하면 학부모에게 나가는가"다**: 메인 그리드는 **인물·공통**(= 검수·발행 대상)이고, **`분류가 어려워요`는 눈감음·흔들림과 함께 하단 섹션 "공개해도 학부모에게 안 보여요"로 내렸다**(CHMO-114 반전). 종전엔 '재분류 대상'이라 메인 그리드에 뒀지만, 검토 UI도 발행 대상도 아닌 앨범(CHMO-357)이 검토 테두리·범례를 공유하는 자리에 섞여 "이것도 검토해야 하나"로 읽혔다 — 14 검토 진척·공개 게이트(CHMO-488)가 세는 범위와도 어긋났다. 판정은 타입 열거가 아니라 파생 필드 `visibleToViewer`(`person`·`common`만 true — `api/mappers.ts` 단일 원천). 섹션 라벨을 명사(`공개 제외`)가 아닌 문장으로 둔 건 선생님은 이 앨범들을 **지금 이 화면에서 보고 있어서** 누구에게 안 보이는지가 빠지면 자기모순으로 읽히기 때문이다. `분류가 어려워요` 카드의 `N장 · 재분류 대상` 메타·🤔 커버는 그대로 남아 할 일은 계속 드러난다. 범례는 메인 그리드 몫이라 인물·공통이 하나도 없으면 걷는다. **14의 비공개 앨범 고지(CHMO-521)와 한 짝**이다 — 같은 사실(학부모에게는 인물·공통만 나간다)을 08은 구획으로, 14는 문장으로 말한다.
- **확정(CHMO-114)**: ① 앨범 카드 커버는 `Album.coverThumbnailUrl`(파생 필드 — `coverPhotoId`만으론 URL 조립 불가)로 노출. ② 레이아웃 = **3열 그리드** + **하단 별도 섹션** + 범례(구획 기준은 위 CHMO-523 확정 — 원안은 인물·공통·분류어려움 그리드 + 품질 제외 섹션). 앨범/사진이 프레임(844)을 넘을 수 있어 그리드는 스크롤, 하단 액션([공개 전 요약보기])은 고정. ③ 인물 앨범 이름수정(모임 전파)은 **09 앨범 상세 헤더 ✎**(CHMO-115) + **08 그리드 카드 이름 줄 탭**(CHMO-400, 2026-07-22 피드백으로 "08엔 진입점 없음" 결정을 뒤집음 — 이름 뒤 인라인 ✎ 힌트, 텍스트 흐름 안이라 이름 전폭 2줄(CHMO-354) 유지. 커버 오버레이 칩 안은 시안 검토에서 기각. 카드 나머지 영역 탭 = 09 진입 그대로, 인물 앨범만 적용, 모달·이름전파 계약은 09와 동일 — CHMO-522에서 이 모달이 앨범 설정 시트로 넓어졌다).
- **확정(CHMO-411)**: **표시 정렬은 FE 소유** — 인물(이름 가나다순, '이름 없음'은 인물 그룹 뒤) → 공통 → 분류가 어려워요, 같은 값은 albumId 고정. **검토 상태와 무관**해 검토 완료해도 앨범 위치가 바뀌지 않는다(실 BE 응답은 미검토 우선+albumId(CHMO-336)라 그대로 쓰면 검토 때마다 순서가 튐 — 목도 실 BE 규칙으로 응답). 정렬 유틸은 `src/lib/albumSort.ts` 단일 원천, **14 미리보기·15 뷰어 앨범 목록도 같은 규칙**(09-1 이동 시트 추천은 유사도 순 — BE 소유라 제외).

### 09. 앨범 상세 · node `211:1685`
- **목적**: 앨범 내 사진 검토/보정.
- **요소**: 헤더 `‹ {이벤트명}`, 앨범명("김민준") + **인물은 `[✎ 앨범 설정]`**(특수 앨범은 `🗑`), 사진 그리드(일반 모드 사진 탭 = 라이트박스 크게 보기), `선택` 모드 토글, 선택 시 하단 액션 `[삭제]` `[옮기기]`, `[검토 완료]`.
- **액션**: 선택 모드→사진 체크 → 삭제(`DELETE /photos`, **현재 앨범에서만 제거 = 연결 해제**, 다른 앨범엔 유지, 휴지통 없음) / 옮기기(→09-1) · 검토 완료(`PATCH /albums/:id` `{ reviewed: true }` — **앨범 내 전 사진 일괄 검토**, 검토 상태는 사진 단위).
- **상태**: 선택 0장 시 삭제/옮기기 비활성, 삭제 확인 다이얼로그(warn 색, "이 앨범에서 제거" 문구 · 다른 앨범엔 유지됨 안내).
- **확정(CHMO-114)**: `[검토 완료]`는 비선택 모드에서도 하단에 노출(앨범 단위 일괄), 전 사진 검토 완료면 비활성(`검토 완료됨`). **선택모드의 검토 완료는 선택과 무관하게 앨범 전체가 대상**이라 확인 다이얼로그로 안내(뷰어 공개 고지 포함). **삭제 확인 문구는 결과를 분기**한다 — 선택 사진 중 이 앨범이 마지막 연결인 것이 있으면 "완전 삭제(복구 불가)"를 명시. 사진이 프레임을 넘을 수 있어 그리드는 스크롤·하단 액션은 고정, 저장/삭제 진행 중엔 조작 잠금. (검토 완료는 CHMO-114에서 **단방향** — '검토 완료됨'에서 되돌리는 토글은 미도입, 실수로 학부모 공개 사진을 내리는 위험 회피.)
- **확정(CHMO-115)**: ① `[옮기기]`(선택모드) → **09-1 사진 이동 바텀시트** 실 UI(유사도 추천 + 공통, 이동=연결 교체). ② **인물(person) 앨범만** 앨범명 옆 `✎ 이름`으로 이름 변경(→ CHMO-522에서 `[✎ 앨범 설정]` 시트로 확장, 위 참조) → **모임 단위 인물(personId) 이름을 갱신해 전 이벤트에 전파**(특수 앨범은 미노출). 로컬 캐시가 없어 현재 앨범만 refetch하고, 다른 이벤트 앨범은 다음 진입 시 갱신된 이름으로 조회. 이름 수정 모달은 이벤트명 수정과 **공용 `RenameModal`** 로 통합.
- **확정(CHMO-522) — 앨범 설정 시트(`AlbumSettingsSheet`)로 앨범 조작을 한 곳에 모은다**: 인물 앨범의 헤더 버튼은 `[✎ 앨범 설정]` **하나**고(종전 `✎ 이름` + `🗑` 두 버튼 대체), 시트 안에 ① 아이 이름 수정(이름전파 계약 그대로) ② **학부모 연결/해제** ③ 앨범 삭제 진입이 순서대로 있다. 08 카드 이름 줄 탭도 같은 시트를 여는데 **삭제만 없다**. 특수 앨범(공통·분류어려움·품질)은 이름·연결 대상이 아니라 종전처럼 `🗑`만 남는다.
  - **학부모 연결은 20 초대 관리의 반대 방향**이다: 20-1은 학부모를 골라 아이를 붙이고(`ChildLinkSheet`), 여기선 아이(앨범)를 보면서 학부모를 붙인다. 매핑이 다대다(다자녀·부모 2인)라 두 경로가 같은 API를 공유한다(`POST`/`DELETE /groups/:id/person-parents` — 초안 §4). 연결 단위가 **`personId`(모임 단위 인물)**라 연결하면 그 모임 **모든 이벤트**에 걸쳐 적용된다 — 시트 문구도 그렇게 말한다. 두 진입점을 함께 두는 이유: 학부모 한 명에게 여러 아이를 붙일 때는 20이 빠르고, 검수하면서 "이 아이 학부모가 누구였지"를 처리할 때는 이 시트가 빠르다.
  - **연결된 학부모 = 칩 + `✕`(확인 다이얼로그)** · **미연결 = 명단 행 + `[연결]`**(신청 원문 `신청: 서연`을 함께 보여 누가 이 아이의 학부모인지 알아볼 단서를 남긴다 — §2 원문 보존). 이름 저장은 성공 시 시트를 닫고(호출부가 든 `album` prop이 옛 이름이라 열어 두면 부제·placeholder가 어긋난다), 연결/해제는 시트를 유지하고 명단만 다시 읽는다(연달아 여러 명 붙이는 자리).
  - **명단 조회 실패는 이름 수정을 막지 않는다** — 섹션 안 인라인 재시도 한 줄로만 알린다(20과 같은 결). 멤버 조회가 TEACHER 전용이라 구계약 실 BE에선 이 섹션만 빈다(`person-parents`·`members`는 실 BE 미구현 — 목으로만 동작).
  - 시트 본문은 학부모가 많으면 프레임을 넘기므로 **`BottomSheet bodyScrollable`**(신설)로 본문만 스크롤한다 — 기본 시트는 `touch-action: pan-x`로 세로 팬을 JS 끌기에 넘기는데, 그 값이 **자손의 세로 스크롤까지 막아** 시트 안 목록이 스크롤되지 않았다. 이 모드에선 세로 팬을 브라우저에 남기고 끌어내려 닫기는 그랩 핸들·제목 영역이 맡는다(기존 시트 3곳은 prop 미지정 = 동작 불변). ⚠ iOS 실기기 확인 항목.
- **확정(CHMO-242)**: 검수 사진 크게 보기(2026-07-14 시연 피드백). ① **일반 모드 사진 탭 = 라이트박스**(16 뷰어 라이트박스를 **공용 `PhotoLightbox`로 승격** — 좌우 스와이프·←/→ 키 이동, `n / N` 카운터, 인접 프리로드). 스타일은 **iOS 사진 앱풍 라이트 크롬**: 흰 배경 풀블리드 + 상단 ✕/카운터·하단 아이콘 툴바(반투명 blur 바, SF Symbols풍 라인 아이콘 — 다크 스크림 아님). 선택모드에선 탭 = 선택 유지 — 선택모드 진입 롱프레스는 CHMO-243 몫(제스처 정합 확정). ② **검수 맥락 배지**: 검토 상태(`검토완료`/`미검토`) + 사진 플래그(`눈감음`/`흔들림`). ③ **하단 툴바 액션**: `[저장]`(개별 저장 — 원본 `downloadUrl`, 업로더 다운로드 용도 포함) · `[옮기기]` · `[삭제]`(현재 1장 대상 — 선택모드와 같은 확인 다이얼로그·09-1 시트 공유, 처리 후 다음 사진으로 이어짐. 삭제는 iOS 휴지통처럼 맨 오른쪽·warn 색). ④ 사진 단위 **'검토' 액션은 미도입** — BE에 사진 단위 검토 API가 없다(앨범 일괄 `PATCH /albums/:id`뿐, api-spec 명시). 앨범 zip 일괄 다운로드도 제작자용 엔드포인트가 없어 제외.
- **확정(CHMO-488, 2026-07-28 정책 변경)**: ① `[검토 완료]`에 **확인 다이얼로그 복원**(CHMO-413에서 뺐던 것) — 검토 **해제가 폐지**돼 되돌리려면 사진을 지우는 수밖에 없다. CHMO-413의 제거 근거("되돌릴 수 있는 표시라 마찰 불필요")가 정책상 사라졌다. 문구는 대상 장수 + 비가역 + 대안("빼야 할 사진은 먼저 삭제하거나 옮기세요"). ② **공개된(`published`) 이벤트에서의 이동은 확인 다이얼로그를 거친다**(09-1) — 옮긴 사진이 `reviewed`·`published`를 유지해 학부모 화면에 즉시 반영되므로 오탭 한 번이 곧 잘못된 노출이다. 미공개 이벤트는 종전대로 즉시 이동(아직 아무도 못 보니 마찰 불필요). 이벤트 상태는 앨범 응답에 없어 09가 `GET /events/:id`를 따로 읽고, **조회 실패 시엔 경고 없이 종전 동작**(겪지 않을 일을 겪은 척하지 않는다).
- **확정(CHMO-521)**: `[검토 완료]` 성공 시 08로 복귀하지 않고 **다음 미검토 앨범의 09로 바로 이어 간다**(CHMO-414 반전 — 검토는 앨범 단위로 반복하는 작업이라 08 복귀는 앨범 수만큼 왕복을 만들었다). 다음 대상 규칙은 `src/lib/reviewFlow.ts` 단일 원천: **08 그리드 표시 순서**(`albumSort`)에서 **현재 앨범 다음부터** 찾고 끝나면 앞쪽으로 순환 · 후보는 **인물·공통 + 사진 보유 + 미검토 잔여**(특수 앨범은 검토 UI가 없어(CHMO-357) 넣으면 무한 루프 · `unreviewedPhotoCount`가 없으면(계약상 optional) 후보에서 제외). **남은 앨범이 없으면 14 공개 요약으로 보낸다** — 그때가 곧 공개할 차례다. 이동은 09→09·09→14 모두 **replace**(검토 완료가 비가역이라 지나온 앨범을 되짚을 이유가 없고, 09가 쌓이면 08로 나가는 데 뒤로가기를 앨범 수만큼 눌러야 한다 — 어느 단계에서 뒤로가도 08로 나간다). 앨범 목록은 09 진입 시 미리 읽고(완료 시점에 읽으면 그 대기가 이동 앞에 붙는다) **조회 실패 시엔 종전대로 08 복귀**(검토는 이미 성공했으니 에러로 알리지 않는다). 09→09는 같은 라우트라 컴포넌트가 재사용되므로 `key={albumId}`로 화면 상태(선택모드·라이트박스·busy)를 새로 만든다.
- **API**: `GET /albums/:id`, `PATCH /albums/:id`, `DELETE /photos`, `GET /events/:id`(이동 확인 판정용), `GET /events/:id/albums`(다음 검토 대상 판정용)

### 09-1. 사진 이동(바텀시트) · node `211:1866`
- **목적**: 선택 사진의 분류 보정 — **현재 앨범에서 빼고 대상 앨범으로 이동**(다대다에서 연결 교체, 복사 아님).
- **요소**: "다른 사진첩으로 옮기기 / 유사도가 높은 순으로 추천해요", 추천 앨범 리스트(이름만 — 와이어프레임의 유사도 %는 폐기, 아래 확정), `공통 사진첩` 옵션.
- **액션**: 대상 선택 → `POST /photos/move`(`sourceAlbumId`+`targetAlbumId`) → 09로 복귀(반영).
- **확정(CHMO-115)**: 09(앨범 상세) 위 **바텀시트**로 구현(별도 라우트 없음 — 초대/공유 시트와 동일 패턴). 추천은 원형 아바타 가로 스크롤(공통만 `사진첩` 라벨). 열릴 때만 `move-suggestions` 조회(선택 사진 `?photoIds=`), 이동 성공 시 시트 닫고 선택 해제 + 상세 refetch. 이동 중 시트 조작 잠금.
- **확정(2026-07-29) — 유사도 % 미표시**: 실 BE가 `similarity`를 더는 보내지 않아 추천 타일에서 % 표기를 걷어냈다(이름만 남는다). **정보가 사라지는 건 아니다** — 추천 목록의 순서가 곧 유사도 순이라 "위쪽이 더 닮았다"는 신호는 그대로다. 종전 코드는 `similarity !== null`로만 걸러서, 키가 통째로 빠진 응답이 오면 `NaN%`가 새어 나올 자리였다(매퍼가 `?? null`로 정규화 + 계약 테스트로 고정). 필드 자체는 타입·매퍼에 남겨 둔다(옛 응답·픽스처 호환).
- **확정(CHMO-488)**: 공개된 이벤트에서만 대상 탭 → **확인 다이얼로그**("공개된 이벤트예요. 사진 N장을 옮기면 학부모 화면에 바로 반영돼요") → 이동(`confirmImmediateExposure` prop, 09가 이벤트 상태로 판정). **"새 앨범" 타일은 예외** — 이름 입력 + `[만들기]`가 그 자체로 의도 확인이라 다시 묻지 않는다.
- **API**: `GET /albums/:id/move-suggestions`, `POST /photos/move`

### 14. 공개 요약 · node `211:1723`
- **목적**: 공개 직전 최종 확인 + 공개 실행.
- **요소**(CHMO-531 반영): 헤더 `‹ 앨범`, **큰 제목 = 이벤트명**(2줄 클램프), 부제 `공개 요약 · 사진 N장`, **요약 통계 2칸**(`검토된 앨범 N` · `검토 남은 앨범 N`), **`검토가 남았어요`** 구획(미검토 앨범 카드 그리드 — 탭하면 09), **`공개하면 이렇게 보여요`** 구획(발행 대상 앨범 카드), 공개되지 않는 앨범 고지, 하단 고정(게이트 문장 + `[공개하기]`).
- **액션**: 미리보기(학부모 뷰 프리뷰) · `[공개하기]`→`POST /events/:id/publish` → 이벤트 상태 `공개됨`(→ 모임 학부모 공유 목록에 노출; 공유 링크/비밀번호는 모임 단위).
- **상태**: 미검토 사진 존재 시 **[공개하기] 비활성 + 남은 앨범 안내**(전량 검토 완료가 하드 게이트 — 정책은 기능 명세 참조).
- **확정(CHMO-116)**: ① 미리보기 = **인라인 3열 썸네일 그리드**(뷰어 노출 규칙 적용 사진 최대 6장, 탭 동작 없는 순수 프리뷰) — 별도 프리뷰 화면 없음. 썸네일 URL은 `review-summary.previewThumbnailUrls`(파생값, `coverThumbnailUrl` 선례). 검토된 노출 사진이 없으면 빈 안내. ② `[공개하기]`는 항상 확인 다이얼로그(학부모 공개는 되돌리기 어려운 외부 노출) — 남는 경고는 **보일 사진 0장**뿐(공개해도 학부모에겐 빈 이벤트 — 거짓 안내 방지). ③ 공개 성공 시 **05 모임 상세로 복귀**(공개 완료 배지·학부모 공유 진입 노출). ④ 버튼은 **공개 가능 상태(`review`/`ready`)에서만 활성** — `published` 재진입은 `공개 완료됨` 비활성, empty/analyzing 딥링크도 비활성(서버 400 방어). ⑤ 공개 실패(이미 공개 등) 시 event·summary **재조회**로 stale 화면 방지(동시 작업 = 정상 시나리오). **05 배지·뷰어 목록 노출은 기존 코드/목이 처리**(별도 작업 없음).

BE에 중복 제거된 `publishablePhotoCount`를 요청해 두고(CHMO-505), 받으면 첫 칸을 '공개할 사진'으로 전환한다. `albumCount`(BE totalAlbums) 매핑은 소비처가 없어져 제거.
- **확정(CHMO-398)**: 화면명 '공개 전 검수' → **'공개 요약'**, 08 진입 CTA → '요약 보기' — 사진 단위 작업 '검토'와 층위가 겹치던 '검수'를 사용자 노출 문구에서 제거하고, CTA가 "되돌릴 수 있는 이동"으로 읽히게 한다(되돌릴 수 없는 건 14 안의 `[공개하기]`뿐).
- **확정(2026-07-29)**: 08 진입 CTA → **'공개 전 요약보기'** — '요약 보기'만으론 무엇의 요약인지, 왜 지금 보는지가 없어 다음 단계(공개)와 이어지지 않았다. '공개 전'을 붙여 이 화면이 공개 동선의 마지막 정거장임을 CTA에서 드러낸다(화면명 '공개 요약'은 그대로).
- **확정(CHMO-521)**: ① **진입점이 둘**이 됐다 — 08 `[공개 전 요약보기]` 외에 **09에서 마지막 앨범을 검토 완료하면 직행**한다. ② **공개되지 않는 앨범 고지**를 미리보기 아래에 둔다: 사진이 있는 특수 앨범(분류가 어려워요·눈감음·흔들림)을 "학부모에게는 인물·공통 앨범만 보여요" + "분류가 어려워요 3장 · 눈감은 사진 2장은 공개 대상이 아니에요"로 알린다. 이유는 그 앨범들이 **검토 동선에 한 번도 등장하지 않기 때문**(CHMO-357) — 검토를 다 끝내고 온 사람에게 그 사진들의 행방이 사라진다. 카드가 아니라 문장인 건 미리보기 그리드가 공개 대상만 담기 때문(CHMO-347), 문구가 시제 중립인 건 공개 전·후 어느 쪽에서 봐도 사실이어야 하기 때문. 데이터는 `ReviewSummary.excludedAlbums`(FE 파생 — BE `albums[]`에서 `!visibleToViewer && photoCount > 0`, 빈 특수 앨범은 알릴 것이 없어 제외).
- **확정(CHMO-531, 2026-07-30 — "수치가 별로고 리즈닝을 해야 한다"·"이벤트 이름이 안 보인다" 피드백)**: 시안 3안씩 두 번 대조 후 **통계=안 B(앨범 단위 2칸)** · **이름 자리=안 나(본문 큰 제목)** 채택.
  ① **통계 3칸 → 앨범 단위 2칸**. 종전 3칸은 같은 사실을 세 번 말했다 — `공개할 앨범`과 `검토 n/m`의 **분자가 같은 수**인데(둘 다 검토 완료된 인물·공통) 화면이 그걸 말하지 않아 관계를 찾게 되고, `n/m`에서 남은 수를 뺄셈하면 아래 안내가 그 결과를 또 말했다. 이제 **`검토된 앨범 N` · `검토 남은 앨범 N`** — 두 칸이 **같은 축(검토)의 앨범 수**라 `N + N = 전체`가 눈으로 더해진다. 왼쪽 칸을 '공개될 앨범'으로 두지 않은 이유(2026-07-30 피드백): 세는 값은 같아도(검토 끝난 인물·공통 = 발행 대상) 오른쪽이 '검토'를 말하는데 왼쪽만 '공개'를 말하면 두 수가 **다른 축처럼 보여** 또 관계를 따지게 된다 — 무엇이 나가는지는 아래 미리보기 구획이 카드로 답한다. 축이 같아지니 published 시제 분기도, 남은 게 0일 때의 예외 표기도 필요 없다(그냥 `0`, 두 칸이 같은 수가 되는 중복이 없다). 검토할 앨범이 아예 없으면(인물·공통 0개) 통계 줄을 통째로 걷는다. **전체 사진 수는 부제로 강등** — 공개될 장수가 아닌 값이 가장 큰 자리를 차지하고 있었다(정확한 발행 장수는 BE `publishablePhotoCount` — CHMO-505 후 전환).
  ② **막고 있는 앨범을 카드로 보여준다**(종전 `인물 2 1장 · 인물 4 3장 · …` 한 줄 나열 폐지). 나열의 문제는 넷 — 숫자 둘이 붙어 오독되고(`인물 2`+`1장`), `1장`이 남은 장수인지 전체 장수인지 알 수 없고, **아직 이름을 안 붙인 인물(`인물 5`)은 텍스트로 누군지 알 수 없고**(단서는 얼굴뿐), 갈 문이 없었다. 08과 같은 앨범 카드 그리드(커버·점선 테두리) + 메타 `N장 남음`(`AlbumCard`에 `metaText` prop 신설 — 값이 없으면(계약상 optional) 기본 메타로 폴백) + **탭하면 그 앨범 09로** → `14 → 09 → 검토 완료 → 다음 09 → … → 14` 고리가 닫힌다(CHMO-521과 한 짝). 미리보기보다 **위**(할 일 먼저 — 08 범례 규칙과 같은 결), 개수 제한 없이 전부 펼친다.
  ③ **게이트 문장은 하단 `[공개하기]` 바로 위**로 옮겼다(`앨범 N개를 마저 검토하면 공개할 수 있어요`) — 스크롤을 내려도 잠긴 이유가 버튼 옆에 남는다. 규칙은 버튼 옆, 수는 목록 위 — 각자 필요한 자리에서 한 번씩.
  ④ **섹션 라벨을 문장으로**: `미리보기` → `공개하면 이렇게 보여요`(published면 `학부모에게 이렇게 보여요`). 명사 `공개될 앨범`을 쓰면 바로 위 통계 칸과 같은 말이 두 번이라, 08 하단 구획(`공개해도 학부모에게 안 보여요`)과 같은 문장 꼴로 맞췄다.
  ⑤ **이벤트 이름이 큰 자리를 갖는다**: 종전엔 `공개 요약`이라는 **화면 종류명**이 큰 제목이고 이름은 회색 13px 부제였다 — 05(모임명)·08(이벤트명)·09(앨범명)가 전부 고유명사를 큰 자리에 두는데 **14만 예외**였다. 08처럼 헤더로 올리지 않고 **본문 큰 제목**으로 둔 이유 둘: 헤더는 한 줄이라 긴 이름이 잘리는데 여기는 곁에 붙는 컨트롤이 없어 **2줄 클램프**로 온전히 보이고(09의 `truncate`와 갈리는 지점 — 09는 이름 줄에 컨트롤이 붙는다), 08과 달리 하단 `[공개하기]`가 늘 붙어 있어 스크롤로 제목이 사라져도 화면의 정체가 흔들리지 않는다. 뒤로가기도 `‹ 이벤트 상세` → **`‹ 앨범`**(08은 스스로를 '이벤트 상세'라 부르지 않는다 — CHMO-522).
  ⚠ **CHMO-530 머지 후 재확인 완료**(2026-07-30): 05가 모임명을 헤더로 올리면서 **본문 큰 제목은 09·14뿐**이 됐다. 그래도 14는 본문 제목을 유지한다 — 05가 상단을 비운 건 이벤트 목록만 스크롤시키기 위해서였고 14엔 그 제약이 없으며, 위 두 근거(긴 이름 2줄 · 하단 고정 버튼이 화면 정체를 잡아 준다)는 05의 변경과 무관하게 성립한다.
  ⑥ **확인 다이얼로그에 이벤트명**(`'{이름}'을 공개할까요?` — 따옴표·`을` 고정은 09 검토 완료/앨범 삭제와 같은 꼴) + 설명에 나갈 앨범 수. 본문 큰 제목이 스크롤로 사라진 뒤 **결정하는 마지막 자리**라 ⑤의 유일한 약점을 여기서 메운다. ⑦ 공개 제외 고지의 가운뎃점 → 쉼표(앨범명 안 공백과 섞여 한 덩어리로 읽혔다).
  ⑧ **앨범 카드 검토 대비를 선 → 면으로**(2026-07-30 "검토와 미검토 카드의 대비가 없다"): 110px 카드에서 2px 선의 색·점선 여부만으로는 두 상태가 같아 보였다. **검토완료 = 채운 면(`surface`) + 갈색 실선 / 미검토 = 빈 면(흰색) + 회색 점선** — 채움 유무가 작은 크기에서 가장 멀리서 읽히고, '다 한 것은 도장 찍히듯 차고 남은 것은 빈 윤곽'이라는 뜻도 맞다(같은 문법: 05 모임 색면 ↔ 이벤트 흰 카드, CHMO-515). 새 색을 만들지 않고 기존 토큰을 쓴다. **`AlbumCard` 공용 변경이라 08·14·00-T가 함께 바뀌고**, 08 범례도 `점선=미검토 · 채운 면=검토완료`로 따라갔다(`docs/design/screen-system.dc.html` §06 동기화).

- **확정(CHMO-117)**: ① 개별 다운로드 = 사진 탭 → 라이트박스(크게 보기 + `[⤓ 이 사진 저장]` — 와이어프레임 없는 표면, 최소 구현). ② `[⤓ 다운로드]` = 일괄 zip(`/download`의 `downloadUrl` 트리거). ③ `[↗ 공유]` = Web Share API, 미지원·실패 시 링크 복사(사용자 취소만 무시) — 공유 대상은 잠금 해제 입구 URL(`/share/:token`, 뷰어 딥링크 아님). (CHMO-242에서 라이트박스가 09 검수와 **공용 `PhotoLightbox`** 로 승격 — iOS 사진 앱풍 라이트 크롬, 좌우 스와이프·카운터·`[저장]` 아이콘 툴바.)
- **MVP 메모**: 다운로드 한도 없음(소개 문서 MVP 제외 항목).
- **API**: `GET /share/:token/events/:eventId/albums/:albumId`, 다운로드 엔드포인트

### 설정 / 프로필 편집 · node `240:53`
- **목적**: 이름 변경.
- **요소**: 헤더 `‹ 설정`, "프로필 편집", 이름, `[저장]`.
- **액션**: 저장 → `PATCH /me`.
- **확정(CHMO-118)**: ① 헤더는 기존 서브형 관례(`‹ 홈` + 타이틀 "설정")로 적용, "프로필 편집"은 본문 제목 — 와이어프레임의 `‹ 설정`은 별도 설정 목록 화면 전제인데 MVP IA에는 그 화면이 없음. ② 이름(데이터 필드는 nickname)은 `GET /me`로 프리필, `[저장]`은 **실제 변경이 있을 때만 활성**. 저장 중엔 입력 필드도 잠근다(늦은 응답이 입력을 덮지 않게). ③ **로그아웃 버튼 포함**(하단 `[저장]` 위 secondary, MVP 스코프 확정 사항) — 앱 유일의 로그아웃 표면이라 프로필 로딩/실패 중에도 상시 노출. 토큰 삭제 후 01 로그인 진입으로 복귀.
- **확정(CHMO-557)**: "PIN 번호 변경" 필드 삭제 — PIN 로그인 화면이 사라져 PIN을 쓸 곳이 없다. `PATCH /me`의 pin 계약 자체는 api 계층에 남는다(화면이 안 실을 뿐).
- **API**: `GET /me`, `PATCH /me`

## 5. 구현 시 확정 필요 항목(요약)
1. 홈의 `관리자` 배지/`📌` 고정 — 권한 제거에 따라 미표시(추후 재도입 여지).
2. `⧉ 학부모님에게 공유` — **모임 단위 공유로 확정**(05에 위치, `GET /groups/:id/share`). 학부모 전용 비밀번호(모임 비밀번호와 별개, 생성 시 자동), 비번 후 공개 이벤트 목록(15-L)에서 선택. (더 이상 미정 아님 · 신규 화면 15-L은 와이어프레임 없음 → 시안 필요)
3. 품질 제외 사진 라우팅 — `눈감은 사진`/`흔들린 사진` 앨범으로(08 기준), 업로드 카피와 정합 맞추기.
4. `공통(common)` 앨범 정의 — 앨범↔사진 다대다 확정으로 "다수 인물"은 각 아이 앨범에 모두 들어가므로, `공통`은 **특정 아이로 분류되지 않은 사진(단체/배경 등)**으로 좁혀 정의(구현 시 확정).
5. 도메인 `classpic.app` → 치즈모아 도메인(placeholder).
6. 온보딩(00) 완료 상태 저장 위치 — FE 로컬 플래그(기기별) vs `/me` 필드(계정별). MVP는 로컬로 가고, 서버 저장은 BE 협의 후 별도 스토리(CHMO-481 제외 항목).
7. **20 초대 화면의 '참여 코드' 텍스트 노출**(CHMO-513에서 파생 · 시트 폐지로 자리만 옮겨진 미정 — CHMO-520) — 홈의 참여 코드 입력이 사라져 받는 쪽에 넣을 곳이 없다. 링크 복사·카카오톡 공유만 남기고 코드 문자열을 감출지, 참고용으로 남길지 미정. 링크가 유일한 경로라면 코드는 죽은 정보이므로 감추는 쪽이 일관되지만, 링크가 막힌 환경(문자·구두 전달)의 폴백을 잃는다.

> **참고**: 다대다(사진=여러 앨범), 삭제=현재 앨범에서만 제거(연결 해제), 옮기기=연결 교체, 인물 이름=모임 단위 공유(rename 그룹 전파)는 ERD 반영으로 **확정**됨(더 이상 미정 아님).
