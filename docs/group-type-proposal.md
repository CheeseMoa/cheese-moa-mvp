# 모임 유형 전환(일반/기관) — B2C 개방 정책 제안

> **협의용 제안 문서입니다(확정 아님).** 2026-08-06 논의에서 확정된 방향 + 열린 질문을 담습니다.
> 합의된 계약은 이후 `api-spec.md`·`feature-spec.md`·`screen-spec.md`에 반영합니다.
> **BE 계약이 필요한 항목은 목 선행 없이 BE 착수를 먼저 협의합니다**(2026-07-20 방식 전환).

## 0. 배경 — 왜 여는가

- **B2B 단독 진입의 한계**: 유치원만 바라보면 사용자 확보·수익화까지 너무 오래 걸린다(2026-08-06 판단).
- **실질적으로 셀프서브가 아니다**: 절차상으로는 선생님 혼자 가입→업로드→공개까지 가능하지만, 보호자 동의 확인(attestation, CHMO-516)을 **정직하게** 체크하려면 얼굴 특징정보(민감정보) 처리까지 커버하는 보호자 동의를 미리 확보해야 한다. 유치원이 연초에 걷는 통상의 사진 동의서는 이를 커버하지 않으므로, 사실상 원장·기관을 통해 동의서를 다시 걷어야 하고 — **"기관 보고 없이 선생님이 그냥 쓰는" 경로가 실질적으로 막혀 있다.**
- **워딩·구조가 유치원으로 좁혀져 있다**: 선생님/학부모/자녀/원아 어휘와 동의 모달·고지 배너가 전 화면에 깔려, 일반 사용자는 진입 불가하고 선생님에게도 "기관이 정식 도입해야 하는 무거운 도구"로 읽힌다.
- 방향: **서비스의 기본 얼굴을 "모임 사진을 올리면 사람별로 자동 정리되는 일반 도구"로 전환**하고(친구·가족·동호회·그리고 선생님도), 기관용 관리 장치는 **비즈니스 모임 유형** 뒤로 접는다.
- 미배포·사용자 0명이므로 **데이터 마이그레이션은 없다.**

## 1. 확정 모델 (2026-08-06 논의)

모임 생성 시 유형을 정하며(생성 후 전환 없음 — Q8), **두 유형을 동시 출시**한다.

| | 일반 모임 (권한 없음) | 비즈니스 모임 (권한 있음) |
|---|---|---|
| 합류 | 링크 + 비밀번호 입력 → **즉시 멤버**(승인 없음) | 링크 + 비밀번호 입력 → 신청(PENDING) → 승인 |
| 역할 | **전원 동일**(역할 없음) | TEACHER/PARENT + 아이 연결 (현행) |
| 노출 | **분류 완료 즉시 전원 열람** — 검수·공개 단계 자체가 없다 | 검토 → 공개 → 학부모는 자기 아이 이벤트만 (현행) |
| 편집 | **상시** — 이동·이름·삭제가 라이브 앨범에 즉시 반영, 확인 다이얼로그 최소화 | 현행 (published 이동은 확인 다이얼로그) |
| 추가 업로드 | **허용** | **허용** (재공개 경로 복원 필요 — §5) |
| 동의 게이트 (생성·업로드·신청) | 없음 | 없음 — **법적 동의는 가입(01-A) 1회로 일원화**(2026-08-06 2차 · ⚠ 변호사 확인 필수) |

확정 근거·의미:

- **일반 모임 = "멤버 전원이 지금의 선생님인 모임"**. 학부모 쪽 장치(승인·역할·아이 연결·노출 필터·18/19 화면)를 새로 만드는 게 아니라 *안 쓰는* 것이라 구조 변경이 가장 적다.
- **일반 모임에 "공개"라는 단계는 없다**. 앨범은 항상 라이브고 항상 편집 가능하다. 현행 구조에서도 이동·삭제는 published 사진에 즉시 반영되므로(학부모 화면 즉시 갱신), 기술적으로 자연스러운 방향이다.
- **노출 시점은 분류 완료 즉시**(현행 구조 그대로, BE 변경 없음). 업로드 직후 분류 전 원본을 "전체 사진"으로 먼저 보여주는 안은 **후속 개선 후보**로 남긴다(분류 전 사진 목록 API 신설 필요).
- **참여 비밀번호: 생성 화면에서만 사라진다**(3차 — 2차 '전면 폐지'를 정정): 비밀번호는 전 유형 **자동 발급**되어 초대 메시지에 링크와 함께 동봉되고, **합류하는 쪽은 입력한다**(1차 결정 유지). 생성 화면(03-2·03-3)에는 비밀번호 입력란이 없다 — 비즈니스형도 마찬가지.
- **동의 수집은 가입(01-A) 1회로 일원화**(2026-08-06 2차): 모임 생성(03)의 보호자 동의 확인 · 업로드 428 게이트(CHMO-514·516) · 참여 신청(02-2)의 인물(자녀) 동의(CHMO-586·587)를 전부 걷어낸다 — 02-2는 **인물 이름 입력 → 신청의 단일 화면**이 된다. ⚠ 가입 동의만으로 관리자가 올리는 제3자(아동 포함) 사진·얼굴 처리가 커버되는지가 §9 변호사 확인의 최우선 질문이 되고, BE 게이트·동의 기록의 폐지/비활성 협의가 필요하다.

### 1-1. 화면 설계 확정 (2026-08-06 와이어프레임 문답)

와이어프레임 정본: 피그마 페이지 **'모임 유형 전환 (B2C) — 2026-08'**(섹션 4개 · 화면 22장 + 커버 노트).

- **유형 명칭 = 일반 모임 / 비즈니스 모임** — 배지는 비즈니스 모임에만 '비즈니스'. **03 유형 선택 = 정사각 카드 2장**(3차 확정 — 2차 '유형을 묻지 않는다' 안 정정): 카드에는 **유형 이름 + 쓰임새 예시 한 줄만** 담는다("일반 모임 — 가족 여행, 친구 모임" / "비즈니스 모임 — 유치원, 여행사, 학원"). 1차의 긴 설명형 카드와 "친구·가족과" 워딩은 폐기. 선택하면 이름 입력 화면(03-2·03-3 — 유형 pill 표시, 이름뿐)으로 간다.
- **역할 워딩 = 관리자 / 멤버** (구 선생님/학부모). 워딩 중립화는 **비즈니스형 화면 포함 전면 적용** — '아이 연결'→'인물 연결', '자녀 이름'→'(사진 속) 인물 이름', 14 고지 "학부모에게는"→"멤버에게는". 유치원 어휘의 유일한 잔존처는 03 유형 카드의 업종 예시.
- 일반형 화면 확정: 08 하단 CTA **[＋ 사진 추가] 단독** · 09 하단 **[다운로드] 단독**(검토 완료 없음) · 초대는 **20 라이트 화면**(링크+비밀번호 동봉 공유, 멤버 명단·내보내기 — 역할 탭·신청 섹션 없음) · 02-1은 모임명·멤버 수 + 비밀번호 입력 모달 → [참여하기].
- **회색 보조 문구 최소화**(2차 — "자잘한 회색 워딩이 많다" 피드백): 자명한 기능에는 설명 문구를 달지 않는다. 안내가 꼭 필요한 곳(빈 상태·승인 흐름 등)만 한 줄로.
- 비즈니스형 05 하단 [초대 관리]에 **신청 수 인라인 뱃지** 유지(현행 CHMO-530 관용).

## 2. 포지셔닝·법적 구도 전환

**"라이트하게"는 법적 방어의 포기가 아니라, 방어 구조를 '게이트'에서 '약관+포지셔닝'으로 옮기는 것이다.**

| | 현행 | 전환 후 |
|---|---|---|
| 서비스 정의 | 유치원 행사 사진을 AI가 아이별 앨범으로 분류 | **모임 사진을 올리면 사람별로 자동 정리** (일반 도구) |
| 법적 방어의 중심 | 화면 게이트 (보호자 동의 확인·자녀 동의·승인제) | **약관(업로더 책임 조항) + 멤버 본인 가입 동의 + 비회원 피촬영자 조항**(처리방침 §4④·§10⑤ 기존 초안) |
| 아동 민감정보 | 서비스 정의 자체 → 모든 흐름에 장치 내장 | **비즈니스 모임 유형의 관심사** → 게이트는 비즈니스형에만 |
| 비교 대상 | (없음 — 독자 구조) | 밴드·구글 포토의 얼굴 그룹핑이 서 있는 자리 |

- 워딩 중립화: **기본 흐름(일반 모임·공통 화면)에서 선생님/학부모/자녀/유치원 어휘를 제거**하고, 비즈니스형 흐름 안에서만 쓴다. 서비스 소개(`mvp-explanation.md`)·스토어 등록 문구도 재정의 대상.
- 가입 동의 4종(01-A)은 **유형 무관 유지** — 멤버 본인의 얼굴 특징정보 동의는 서비스 본질이라 뺄 수 없다. 무로그인 회귀도 없다(2026-07-17 자문 유지 — 낮추는 건 로그인 *이후*의 마찰이다).
- 이 구도 전환의 유효성이 **변호사 확인의 핵심 질문**이다(§9).

## 3. 일반 모임 상세 동작 (FE 안)

- **생성(03)**: 유형 선택(정사각 카드 2장) → 이름 입력. 생성 화면에 비밀번호 입력란·동의 게이트 없음(비밀번호는 자동 발급).
- **초대**: 링크 1종 + 자동 발급 비밀번호(공유 메시지에 동봉). 링크 재발급(기존 링크 무효화)은 유출 대비 안전판으로 검토(Q7).
- **합류(02-1)**: 링크 → 모임명·멤버 수 확인 + 비밀번호 입력 모달 → [참여하기] → **즉시 ACTIVE** → 모임 화면 직행.
- **조회(08/09)**: 화면 재사용. 검토 테두리·배지·[검토 완료]·[공개 전 요약보기]·코치 힌트(publish-gate·album-review)는 비즈니스형 전용이 되고, 일반형 앨범 카드는 검토 상태 표시가 없는 단일 스타일. 특수 앨범 하단 구획 라벨("공개해도 학부모에게 안 보여요")은 일반형 재워딩 필요(예: "분류에서 제외된 사진").
- **편집**: 이동(09-1)·이름 수정·삭제 상시. published 이동 확인 다이얼로그(CHMO-488)는 비즈니스형 전용. 앨범 삭제 확인은 파괴적 동작이라 유지.
- **저장**: 기존 파이프라인(CHMO-473) 그대로.
- **14 공개 요약·18/19 학부모 화면·20 승인/아이 연결**: 일반형에 없음. 일반형의 초대 화면은 링크 공유 + 멤버 명단(내보내기)만.

## 4. 비즈니스 모임 변경분

**현행 유지가 원칙**이고 변경은 하나 — §5의 추가 업로드 허용에 따른 **재공개 경로 복원**. 승인제·역할·아이 연결·검수·공개·동의 게이트·노출 필터는 그대로 두되, "기관 계약(위탁·세금계산서 등)이 필요한 곳만 컨택하는 B2B 트랙"으로 포지셔닝이 바뀐다. 컨택은 제품 게이트가 아니라 영업 채널이다.

**모든 유형에서 이벤트에 사진을 계속 추가할 수 있다**(2026-08-06 확정). 업로드 1회 정책(CHMO-486, 2026-07-28)의 전면 반전이며, 되돌릴 것들:

| 영역 | 내용 |

| BE | 2회차 등록 거부 게이트(CHMO-485) 제거 · **증분 분석 재가동**(CHMO-215로 2026-07-10 구현했다 정책상 닫은 경로 — 재개방+검증) · `analyzing` 중 등록 400은 유지(동시 분석 방지 안전장치) |

## 6. API/BE 영향 초안 (계약·네이밍은 BE 결정 따름)

- `Group`에 **유형 필드** 신설(예: `type: GENERAL | MANAGED`) — 생성 시 지정, 불변.
- **합류**: 일반형은 join 즉시 ACTIVE(승인제 우회), joinKey **1종**. 비즈니스형은 2종·승인제 유지. **비밀번호 검증은 전 유형 유지**(자동 발급 — 생성 요청에서 password 입력만 사라진다).
- **role**: 일반형 멤버의 role 처리는 Q1 — 단순안은 전원 TEACHER 부여(기존 TEACHER 관문·조회권 전부 재사용, FE·BE 분기 최소).
- **노출 판정**: 일반형은 reviewed/published 플래그 무관 — 분류 완료된 사진 전부 멤버 열람(Q2).
- **검수·공개 엔드포인트**(검토 완료·publish·review-summary): 일반형에서 서버가 거부할지, FE만 숨길지(Q3 — 서버 강제 권장: 학부모 차단을 403으로 강제한 기존 원칙과 동일).
- **동의 게이트 전면 제거**: presign 428(CHMO-514)·참여 신청 동의(CHMO-586 `childConsentVersion`) 폐지/비활성 — 서버 동의 기록은 가입(01-A) 4종만 남는다(BE 협의 필요).
- **학부모 계열 API**(join-requests·members·person-parents·parent-photos): 비즈니스형 전용 — 일반형에서 호출 자체가 없다.
- 어드민 모임 목록·상세에 유형 컬럼 추가(소규모).

## 7. FE 화면 영향 초안

| 화면 | 일반형 | 비즈니스형 |
|---|---|---|

## 9. 변호사 확인 목록 `[[검토필요]]`

1. **포지셔닝 전환의 유효성** — "업로더 책임 조항 + 멤버 본인 동의 + 비회원 피촬영자 조항" 구조가 일반 모임(로그인 멤버 간 공유)에서 아동 사진·비회원 얼굴을 커버하는지. 무로그인 뷰어 폐기 자문(2026-07-17, 제3자 제공)과 어디까지 다른지.
2. **동의 일원화 구조**(2026-08-06 2차) — 생성·업로드·신청의 게이트와 개별 동의를 전부 걷고 가입 동의(01-A)만 남긴 구조로, 관리자가 올리는 제3자(아동 포함) 사진·얼굴 특징정보 처리와 멤버의 인물 열람 신청이 커버되는지. 커버가 안 되면 최소 동의 지점(가입 동의 문구 확장 등) 대안 제시 요청.
3. **약관·처리방침 재구성** — 현행 기관 구도 문구(학부모 회원 조항 등)를 유형 2종 구조로 조정. 업로더 책임 조항 신설.
